# 单盒恢复检查

恢复验证只覆盖当前设备和受本次改动影响的组件，不重复运行已完成且未变化的发布长测。

1. 记录本机身份、原容器、客体磁盘、正在运行的任务与存储状态。
2. 先验证受影响服务进程重启：原数据、任务幂等性、页面恢复、Android/Windows 原运行身份必须保持。
3. 需要整机重启时在已授权维护窗口执行。开机检查存储解锁、本地 Agent、基础服务、办公模型与用户页面，不自动重建客体。
4. 验证至少一部 Android、一台 Windows、常驻办公与浏览器投屏的统一容量。未知状态不能当成已停机释放资源。
5. 保存本次成功或失败结果，清理仅本次创建的测试资源；不能拼接失败与成功运行。

可复用的旧证据只证明其原始范围。此前测试编排保留在 [历史记录](../validation/controlled-restart-qualification-before-single-appliance-20261016.md)，不是当前必跑命令表。当前发布范围以 OpenSpec 单盒任务为准。

## 后台单独重启后的内部连接恢复

Docker 的 `network_mode: service:platform-api` 只声明共享关系；后台容器重启后，
其他仍在运行的容器可能继续持有旧的 Linux 网络命名空间。仅检查容器 ID、
`NetworkMode` 字符串或各自的健康状态不能证明内部连接正常。

主机上的 `teamaibox-namespace-recovery.timer` 每次检查结束后约 15 秒再检查。
它通过安装记录校验容器 ID、镜像和所有权，并对比活进程的网络命名空间。
仅重新连接已经运行但网络错位的内部网关、桌面代理、桌面网关、维护控制器和
节点代理；不重启后台、数据库、Docker、虚拟机、手机或 AI worker，不启动被
主动停止的服务。后台尚未就绪、身份不符或升级中的绑定不一致时保留现场并报错。

恢复成功必须同时满足：共享网络一致、网关能访问后台、真实节点心跳和指标仍在
更新。网络一致但通信失败时只报告失败，不无限重启服务。完整容器替换继续使用
现有 namespace-cohort 升级事务；这个恢复工具不接管未登记容器。

本故障的专项验收：记录其他容器的身份、启动时间和挂载；只重启一次后台；不
手动补启动连接服务，等待定时器恢复；核对心跳、应用目录和页面恢复，并确认
原有客体与模型容器未重启。证据保存在仓库外，不因此重跑投屏、生成或安装长测。
