# 无线投屏

将 Apple 设备的画面投到 Team AI Box 网页，也可以邀请同事一起观看。当前已有 iPhone 和 Mac 实测；未验证的 iPad/系统版本不作兼容性承诺。**仅在浏览器中播放，不再支持 HDMI，不需要连接显示器或停止 GNOME 桌面。**

这是兼容 AirPlay 的功能，不代表 Apple 官方认证，不支持受 FairPlay/DRM 保护的内容。不同 Apple 设备/系统版本仍应以实际测试结果为准。

## 开始投屏

1. 让 Apple 设备、主盒和观看电脑接入同一局域网。使用系统信任的 HTTPS 地址登录主盒。
2. 打开左侧“无线投屏”，选择“仅自己”“指定用户”或“指定团队”，点击“开始接收”。
3. 在 Apple 设备的“屏幕镜像”中选择网页显示的临时接收器名称，输入随机生成的当前 PIN。
4. 发起者的网页会自动加入观看，不需要再点“加入观看”。浏览器如果阻止自动播放或声音，按播放器提示点击播放或开启声音。

等待连接时显示名称和 PIN；收到画面后以播放器为主。分享、观看者和接收器详情放在“更多”中。名称和 PIN 只对当前会话有效，请不要发送到聊天或工单中。

## 邀请其他人

在当前会话的分享设置中选定成员或团队，然后发送观看邀请。邀请必须在对方工作台和投屏页中清楚可发现；对方点击后进入投屏页，接受邀请即可加入观看。仅收到通知不会自动打开画面。

发起者可以移除观看者。观看者主动“离开观看”后不会自动重新加入；需要时可再次点击加入。管理员可以检查状态和强制停止，但不会因此获得他人私人投屏的观看权。

每次加入或重连都会重新检查权限并获取临时观看凭据，不能转发旧链接或凭据来授权别人。观看人数按可用资源决定，不能把控制连接数量当作已经验证的多人音视频性能。

## 断开与结束

- Apple 设备停止屏幕镜像后，网页应显示来源已断开，不继续播放旧画面；接收会话可以继续等待重新连接。
- “离开观看”只退出当前浏览器，不等于停止整个接收器。
- 发起者点击“停止投屏”后，接收器停止广播，所有观看连接结束，临时名称、PIN 和凭据清除。
- 接收会话到期也会自动停止。主盒重启后旧会话不会凭原 PIN 恢复。

## 没有画面时

| 现象 | 处理 |
| --- | --- |
| 搜不到接收器 | 确认网页已开始接收、名称没有过期，并检查设备是否在同一局域网；访客网络或客户端隔离可能阻止发现 |
| PIN 不正确 | 使用网页当前 PIN；多次输错会暂时限制重试，不要使用旧截图里的 PIN |
| 网页没有声音 | 点击播放器的声音按钮，检查浏览器标签页是否静音、电脑输出设备是否正确 |
| 已连接但没有画面 | 检查手机是否仍在屏幕镜像、内容是否受 DRM 保护；查看网页给出的来源/播放器状态，不要把“接收器正常”等同于有媒体输入 |
| 页面提示服务暂不可用 | 点击页面的重新连接；若仍失败，请管理员检查投屏媒体服务，不需要操作 HDMI、KMS 或桌面 |
| 只有某位观看者卡顿 | 检查该电脑网络和浏览器；先让该观看者离开再加入，不必结束其他人的观看 |

## 隐私与维护

默认不录制、不保存用户投屏画面或声音。权限和会话状态会持久保存，PIN、媒体凭据和发送设备名称不进入日志或业务记录。网页和本机控制通信沿用既有加密保护。

容量不足应在开始前明确提示，不应卸载常驻办公模型。页面更新不应重启模型、手机或主盒；媒体服务维护可以结束开发测试会话，但必须清理该会话的广播和临时资源。回退只使用健康的浏览器投屏版本，不恢复已经取消的 HDMI 接管。

## 管理与版本边界

管理员只把严格通过当前验收清单的 Apple 设备、系统和协议版本列为支持；**没有列入清单的协议版本按不支持处理**，不会为了“兼容”而退回未配对、明文或较弱算法。iPhone 的一次通过不能代替 iPad 或 macOS，也不能推断其他系统版本已经通过。

当前产品只承诺同一局域网内、经 PIN 配对和认证加密后的浏览器观看。FairPlay/DRM 受保护内容不在支持范围内。一个和八个浏览器是验收档位，不是写死的产品上限；更多观看者由当时可用内存、网络和媒体资源决定，准入失败必须明确显示，不能静默降低画质或恢复 HDMI 输出。

## 安装、升级、回滚和卸载

1. 先确认要替换的投屏服务和版本，保留当前健康版本供回退；不要重建手机或办公模型。
2. 媒体服务升级前停止当前测试投屏，确认接收器不再广播、观看连接结束。只更新网页时不需要替换媒体服务。
3. 更新后检查服务健康、打开正式 HTTPS 页面，验证开始、观看和停止。网页能打开不代表 Apple 音视频已经通过测试。
4. 更新失败时停止本次新服务，恢复保留的健康浏览器投屏版本；没有健康版本就明确显示不可用，不启用旧 HDMI 方案。
5. 卸载前同样先停止会话、清除临时 PIN/凭据/媒体缓冲，再移除确切属于该服务的资源；清理失败时保留故障状态，不删除其他服务的数据。
