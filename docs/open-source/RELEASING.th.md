# ปลดปล่อยขอบเขต

## แยกสิ่งประดิษฐ์

1. **MIT ผู้สมัครแหล่งที่มา**: โค้ดต้นฉบับ ข้อมูลจำเพาะปัจจุบัน เครื่องมือสร้าง/ทดสอบและประกาศที่ได้รับการตรวจสอบ ไม่มีประวัติ Git หรือหลักฐานจากห้องปฏิบัติการส่วนตัว
2. **เนื้อหาของบุคคลที่สาม**: แหล่งที่มาต้นน้ำ/ไบนารี/โมเดลที่แน่นอนพร้อมใบอนุญาตและการระบุแหล่งที่มาของตนเอง ภาระผูกพันของแหล่งที่มา Copyleft เดินทางด้วยไบนารี
3. **แพ็คเกจอุปกรณ์ออฟไลน์ที่สมบูรณ์**: สร้างโดย `install/`; ไม่ได้รับอนุญาตโดยอัตโนมัติสำหรับการแจกจ่ายต่อสาธารณะ ส่วนประกอบ GMS, HunyuanOCR, NVIDIA และใบอนุญาตผู้เยี่ยมชม/เฟิร์มแวร์จำเป็นต้องมีการตรวจสอบเฉพาะสิ่งประดิษฐ์ ห้ามเผยแพร่แพ็กเกจส่วนตัว ชุดโมเดล หรือรูปภาพที่ลงชื่อเข้าใช้ภายใต้ป้ายกำกับ MIT
4. **เว็บไซต์การตลาด**: `website/` รวมถึงเทมเพลตบทความ เนื้อหา แอสเซทการออกแบบ การวิเคราะห์ และการกำหนดค่าการใช้งาน ยังคงอยู่ในพื้นที่เก็บข้อมูล GitHub ส่วนตัว `weerocksllc/teamaibox.com` GitLab เป็นไฟล์เก็บถาวรเชิงประวัติ ไม่ใช่คลังข้อมูลการพัฒนาเว็บไซต์ เว็บไซต์ไม่ได้เป็นส่วนหนึ่งของการเผยแพร่แหล่งผลิตภัณฑ์สาธารณะ UI เบราว์เซอร์ของ Appliance ใน `apps/` ยังคงเป็นส่วนหนึ่งของผลิตภัณฑ์โอเพ่นซอร์ส

สคริปต์การใช้งาน การกู้คืน และการบันทึกหลักฐานในอุปกรณ์เครื่องเดียวในอดีตไม่ใช่เครื่องมือผลิตภัณฑ์ที่ใช้ซ้ำได้ นโยบายการเผยแพร่ไม่รวมสคริปต์และสแนปชอตที่เลิกใช้แล้ว อย่ากู้คืนจากไฟล์เก็บถาวรส่วนตัว เครื่องมือที่เก็บรักษาไว้ต้องการเป้าหมายที่ผู้ปฏิบัติงานจัดหาอย่างชัดเจน แทนที่จะเป็นโฮสต์ บัญชี คอนเทนเนอร์ หรือไฟล์หลักฐานของนักพัฒนา เรียกใช้การสแกนที่ละเอียดอ่อนเสริมและ Gitleaks: รหัสอุปกรณ์ รหัสคอนเทนเนอร์ แฮช GSF และชื่อบัญชีส่วนบุคคลกำลังทดสอบข้อมูลเมตาแม้ว่าจะไม่สามารถใช้ข้อมูลรับรองการเข้าสู่ระบบได้ก็ตาม การล้างข้อมูลประวัติสาธารณะต้องได้รับอนุญาตจากเจ้าของอย่างชัดแจ้ง และต้องไม่เขียนไฟล์เก็บถาวรส่วนตัวหรือแท็กการจัดส่งซ้ำ หลังจากเขียนซ้ำโดยได้รับอนุญาตแล้ว ให้ใช้โคลนสาธารณะใหม่แทนที่จะรวมประวัติที่เลิกใช้กลับเข้าไปในพื้นที่เก็บข้อมูลที่ได้รับการดูแล

พื้นที่เก็บข้อมูลการพัฒนาภายในและแท็กยังคงไม่บุบสลาย ประวัติที่เข้าถึงได้ประกอบด้วยบันทึกการปรับใช้เก่าและสินทรัพย์ SDK ที่เป็นกรรมสิทธิ์ซึ่งเลิกใช้แล้ว จะต้องไม่เปิดเผยต่อสาธารณะไม่เปลี่ยนแปลง ต้นไม้ที่ส่งออกใหม่จะเป็นจุดเริ่มต้นสาธารณะโดยไม่ต้องเขียนประวัติการจัดส่งเดิมใหม่

## การเตรียมพื้นที่

ใช้ **Gitleaks 8.30.1** ซึ่งดาวน์โหลดจาก GitHub อย่างเป็นทางการ และตรวจสอบความถูกต้อง เครื่องมือตรวจสอบจะไม่ติดตั้งแพ็คเกจระบบหรืออัพโหลดข้อมูล เอาต์พุตส่วนตัวถูกละเว้น `.runtime/open-source-audit/` ไม่ใช่ PR สาธารณะ

```sh
python3 tools/open_source_release.py baseline --output .runtime/open-source-audit/before.json
python3 tools/open_source_release.py scan --gitleaks /path/to/gitleaks --output .runtime/open-source-audit/review
python3 tools/open_source_sensitive.py --output .runtime/open-source-audit/project-review.json
python3 tools/open_source_inventory.py
python3 tools/open_source_release.py export --gitleaks /path/to/gitleaks --output .runtime/open-source-audit/source-candidate
```

ผลลัพธ์จะต้องเป็นเส้นทางใหม่ เครื่องมือจะไม่เขียนทับผู้สมัครคนก่อนหน้า ตรวจสอบสถานที่ที่มีการปกปิด ไม่เพียงแต่นับเท่านั้น บันทึกเอกสารการติดตั้งสังเคราะห์ ข้อมูลประจำตัวบูตสาธารณะ ตัวระบุผลบวกลวง และข้อมูลประจำตัวส่วนตัวจริง/ที่เป็นไปได้แยกกัน การสแกนรูปแบบไม่สามารถตรวจสอบข้อมูลรับรองหรือภาพหน้าจอ OCR ได้ ไม่รวมสิ่งประดิษฐ์ไบนารี่ ไม่ได้ประกาศว่าสแกนแล้วสะอาด ผู้ส่งออกต้นทางยอมรับเฉพาะไฟล์ที่รู้จักใน Git และอินพุตที่ไม่ได้ติดตามอย่างชัดเจนใน [release-policy.json](release-policy.json) อินพุตใหม่ที่ยังไม่ได้ติดตามจำเป็นต้องได้รับการตรวจสอบ โดยจะปฏิเสธลิงก์สัญลักษณ์และการข้ามเส้นทาง และปล่อย SHA-256 ต่อไฟล์พร้อมการยกเว้น `website/` จะถูกยกเว้นเสมอ แม้ว่าจะถูกติดตามหรือแสดงเป็นอินพุตที่ไม่ได้ติดตามก็ตาม อย่าคัดลอกไดเรกทอรี `.git` ของที่เก็บส่วนตัวไปยังการชำระเงินสาธารณะ ก่อนที่จะเผยแพร่ ให้ตรวจสอบทั้งแผนผังและคอมมิตสาธารณะที่เข้าถึงได้ทั้งหมดไม่มีไฟล์เว็บไซต์ การลบไฟล์ในการดำเนินการภายหลังจะไม่ลบประวัติเก่า

การตรวจเพิ่มเติมครอบคลุมข้อความ commit/tag ที่เข้าถึงได้ ข้อมูลรับรองและข้อมูลเข้าสู่ระบบแบบค่าคงที่ที่คาดเดาได้ง่าย ตัวระบุอุปกรณ์ และที่อยู่ของสภาพแวดล้อมพัฒนา ข้อมูลทดสอบไม่ได้รับการยกเว้นโดยอัตโนมัติ ต้องอธิบายว่า fixture ที่เก็บไว้แต่ละรายการเป็นข้อมูลสังเคราะห์อย่างไร เก็บค่าลับที่ทราบไว้ในอาร์เรย์ JSON ภายนอกซึ่งมีระเบียน `{id, value, word?}` แล้วระบุไฟล์ด้วย `--denylist` ใช้ ID ที่ไม่มีข้อมูลอ่อนไหว และเก็บไฟล์นี้ไว้นอกไดเรกทอรีซอร์ส รายงานแสดงเฉพาะตำแหน่งและแฮช ไม่แสดงค่าจริง หากพบค่าที่ตรงกัน การตรวจจะไม่ผ่าน ระหว่างทำความสะอาดให้ใช้ `--scope worktree` และก่อนเผยแพร่ให้ตรวจ `--scope all` ในคลังรุ่นใหม่ที่ไม่มี commit แม่ ห้ามเผยแพร่ประวัติเก่าหรือรายงานตรวจสอบส่วนตัว

ค่าเริ่มต้นของผู้ดูแลระบบโรงงานโดยเจตนาเพียงอย่างเดียวคือ `admin / admin`; เปลี่ยนระหว่างการใช้งาน เครื่องมือทดสอบการปรับใช้/เบราว์เซอร์จะต้องได้รับข้อมูลรับรองบัญชีที่มีอยู่ผ่านการป้อนข้อมูลในเครื่องที่ได้รับการป้องกัน บัญชีทดสอบควันที่สร้างขึ้นใหม่ใช้ข้อมูลประจำตัวแบบสุ่มและถูกปิดใช้งานในระหว่างการล้างข้อมูล การล้างข้อมูลที่ล้มเหลวคือการทดสอบล้มเหลว ไม่ใช่การรันที่สำเร็จ การยกเลิกกระบวนการอย่างกะทันหันสามารถป้องกันการล้างข้อมูลได้ ผู้ประกอบการจะต้องกระทบยอดบัญชีชั่วคราวของตนหลังจากการหยุดชะงักดังกล่าว ไม่มีเอกสารสาธารณะที่อ้างว่าข้อมูลรับรองการทดสอบนั้นถูกต้องในปัจจุบัน

เฉพาะจุดเริ่มต้น `install/` ที่ดูแลรักษาไว้เท่านั้นที่เป็นพาธการติดตั้ง clean-appliance การประเมินความเป็นเจ้าของส่วนประกอบอยู่ใน [OWNERSHIP.md](OWNERSHIP.th.md)

ไม่มีคำสั่งใดที่จะผลักดัน Git, เปลี่ยนการมองเห็น, เขียนประวัติใหม่, หมุนเวียนข้อมูลรับรองสด, เปลี่ยนแปลงอุปกรณ์ หรือให้สิทธิ์การแจกจ่ายซ้ำแก่บุคคลที่สาม การเผยแพร่สู่สาธารณะจำเป็นต้องมีจุดหมายปลายทางสาธารณะที่เลือกไว้อย่างชัดเจนและการตรวจสอบอาร์ติแฟกต์ขั้นสุดท้าย เก็บ `delivery-2026-10-22` ไว้ในที่เก็บส่วนตัว
