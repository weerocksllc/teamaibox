# パブリックソースのプライバシー境界

パブリック製品リポジトリは、新しいソースのスナップショットであり、プライベートな開発履歴のミラーではありません。マーケティング Web サイトには独自のプライベート リポジトリがあり、ここには含まれていません。

## 削除されたマテリアル

- 導入テストのアカウント名とパスワード、および個人アカウントのリストを修正しました。
- 過去のデバイス ID を記録したり、プライベートな証拠から結果を主張したりする、1 つのデバイスの展開/回復ラッパーとスクリプト。
- 実際のホスト アドレス、ホーム ディレクトリ、コンテナ/デバイス ID、および過去のメンテナンス スナップショット。保持されたテストでは、明示的に合成フィクスチャを使用します。維持される運用ツールには明示的なターゲット入力が必要です。
- ゲスト ディスク、Android ログイン状態、ブラウザ セッション、インストール パッケージ、モデルの重み、およびプライベートな証拠は、パブリック ソース配布の対象外です。

プライベート アーカイブと元の配信タグはそのまま残ります。このソース クリーンアップでは、アプライアンス アカウント、ゲスト データ、実行中のサービス、Web サイトの展開は何も変更されません。 `admin / admin` の工場出荷時のデフォルト値は意図的に保持されています。それは個人的な資格情報ではありません。管理者は公開前に変更する必要があります。

## レビューと検証

ワークツリーと、公開されているリポジトリ内の到達可能なすべてのコミット/タグの両方を確認します。 Gitleaks プラス `tools/open_source_sensitive.py` を使用します。どちらも、それだけでは低エントロピーのパスワードや個人メタデータが存在しないことを証明するものではありません。コミットされたテスト フィクスチャではなく、プライベートの外部拒否リストを使用して、確認された古いプライベート値を比較します。テスト ファイルを含め、残りの結果を個別に確認します。

クリーンアップ チェックは、ソース ポリシー、合成回帰、構成、および構文のチェックです。彼らは、発見された資格情報を使用してログインしたり、ボックスを再インストールしたり、製品の受け入れを繰り返したりしません。以前の API パッケージ化の修正 (共有 UI ソースとインポート専用のエントリ ポイント チェックを含む) はソースに残ります。

新しいクローンは、廃止されたコミット、参照、またはタグをインポートしてはなりません。リポジトリを削除しても、他の人が既にダウンロードしたコピーはリコールされません。未知の資格情報が決してコピーされていないことをスキャンによって証明することはできません。実際に使用された資格情報は、そのオペレーターによってローテーションされる必要があります。このクリーンアップはそれを回転させたとは主張しません。

ソースのエクスポートとレビューの手順については [RELEASING.md](RELEASING.ja.md) を、ビルドの前提条件と個別に取得したアセットについては [BUILDING.md](BUILDING.ja.md) を参照してください。
