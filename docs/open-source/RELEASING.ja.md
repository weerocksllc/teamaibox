# 境界を解放する

## 個別のアーティファクト

1. **MIT ソース候補**: 元のコード、現在の仕様、レビューされたビルド/テスト ツールおよび通知。 Git の歴史やプライベート ラボの証拠はありません。
2. **サードパーティ素材**: 独自のライセンスと帰属が記載された正確なアップストリーム ソース/バイナリ/モデル。コピーレフトのソース義務はバイナリとともに適用されます。
3. **完全なオフライン アプライアンス パッケージ**: `install/` によって構築されました。自動的にパブリック再配布のライセンスが付与されるわけではありません。 GMS、HunyuanOCR、NVIDIA コンポーネントおよびゲスト/ファームウェア ライセンスには、アーティファクト固有のレビューが必要です。プライベート パッケージ、モデル バンドル、またはサインイン イメージを MIT ラベルで公開しないでください。
4. **マーケティング Web サイト**: `website/` は、記事テンプレート、コンテンツ、デザイン アセット、分析、展開構成を含めて、プライベート `weerocksllc/teamaibox.com` GitHub リポジトリに保存されます。 GitLab は歴史的なアーカイブであり、Web サイト開発リポジトリではありません。この Web サイトは、公開された製品ソース配布の一部ではありません。 `apps/` のアプライアンス ブラウザ UI は、オープンソース製品の一部のままです。

これまでの 1 つのデバイスの導入、回復、および証拠記録のスクリプトは、再利用可能な製品ツールではありません。リリース ポリシーでは、廃止されたスクリプトとスナップショットは除外されます。プライベートアーカイブから復元しないでください。保持ツールには、開発者のホスト、アカウント、コンテナ、証拠ファイルではなく、オペレータが明示的に指定したターゲットが必要です。 Gitleaks と同様に補足的な機密スキャンを実行します。デバイス ID、コンテナ ID、GSF ハッシュ、および個人アカウント名は、使用可能なログイン資格情報でない場合でもメタデータをテストします。パブリック履歴のクリーンアップには明示的な所有者の承認が必要であり、プライベート アーカイブやその配信タグを決して書き換えてはなりません。承認された書き換え後は、廃止された履歴を維持されているリポジトリにマージして戻すのではなく、新しいパブリック クローンを使用してください。

内部開発リポジトリとそのタグはそのまま残ります。到達可能な履歴には、古いデプロイメント記録と廃止された独自の SDK アセットが含まれています。そのまま公開してはなりません。新しくエクスポートされたツリーは、元の配信履歴を黙って書き換えることなく、公開の開始点を提供します。

## 現地での準備

公式 GitHub リリースからダウンロードした **Gitleaks 8.30.1** を使用し、チェックサムを確認します。監査ツールがシステム パッケージをインストールしたり、データをアップロードしたりすることはありません。プライベート出力はパブリック PR ではなく、無視された `.runtime/open-source-audit/` に入ります。

```sh
python3 tools/open_source_release.py baseline --output .runtime/open-source-audit/before.json
python3 tools/open_source_release.py scan --gitleaks /path/to/gitleaks --output .runtime/open-source-audit/review
python3 tools/open_source_sensitive.py --output .runtime/open-source-audit/project-review.json
python3 tools/open_source_inventory.py
python3 tools/open_source_release.py export --gitleaks /path/to/gitleaks --output .runtime/open-source-audit/source-candidate
```

出力は新しいパスである必要があります。ツールが以前の候補を上書きすることはありません。数だけでなく、編集された場所を確認します。合成フィクスチャ、パブリック ブートストラップ クレデンシャル、識別子の誤検知、および実際の/可能性のあるプライベート クレデンシャルを個別に文書化します。パターン スキャンでは、資格情報や OCR スクリーンショットを検証できません。バイナリ アーティファクトは除外され、スキャンされたクリーンとは宣言されません。ソース エクスポーターは、Git で既知のファイルと、[release-policy.json](release-policy.json) 内の明示的な追跡されていない入力のみを許可します。新しい追跡されていない入力はレビューが必要です。シンボリックリンクとパストラバーサルを拒否し、ファイルごとの SHA-256 と除外を発行します。 `website/` は、追跡されているか、追跡されていない入力としてリストされている場合でも、常に除外されます。プライベート リポジトリの `.git` ディレクトリをパブリック チェックアウトにコピーしないでください。公開する前に、ツリーと到達可能なすべてのパブリック コミットの両方に Web サイト ファイルが含まれていないことを確認してください。後のコミットでファイルを削除しても、古い履歴は削除されません。

補足チェックの対象には、到達可能なコミットやタグのメッセージ、推測されやすい認証情報やログイン情報のリテラル、デバイス識別子、開発環境のアドレスが含まれます。テスト用データも自動的には除外されません。残す各フィクスチャが合成データである理由を説明してください。既知の非公開値は、`{id, value, word?}` 形式のレコードを含む外部 JSON 配列に保存し、`--denylist` で指定できます。ID 自体には機密情報を含めず、このファイルをソースのチェックアウト外に置いてください。レポートには場所とハッシュのみが表示され、値そのものは表示されません。既知の値との一致があればチェックは失敗します。整理中は `--scope worktree` を使用し、公開前には親コミットのない新しい公開用リポジトリで `--scope all` を確認してください。古い履歴や非公開の確認レポートを公開しないでください。

唯一の意図的な工場管理者のデフォルトは `admin / admin` です。デプロイ中に変更してください。導入/ブラウザ テスト ツールは、保護されたローカル入力を通じて既存のアカウント資格情報を受信する必要があります。新しく作成されたスモークテスト アカウントはランダムな認証情報を使用し、クリーンアップ中に無効になります。クリーンアップの失敗はテストの失敗であり、実行の成功ではありません。プロセスが突然終了すると、クリーンアップが妨げられる可能性があります。このような中断の後、オペレータは一時的なアカウントを調整する必要があります。テスト資格情報が現在有効であると主張する公開文書はありません。

維持されている `install/` エントリ ポイントのみがクリーン アプライアンスのインストール パスです。コンポーネントの所有権評価は [OWNERSHIP.md](OWNERSHIP.ja.md) にあります。

ここでのコマンドは、Git のプッシュ、可視性の変更、履歴の書き換え、ライブ認証情報のローテーション、デバイスの変更、またはサードパーティの再配布権限の付与を行いません。公開リリースには、公開先を明示的に選択し、成果物を最終的にレビューする必要があります。 `delivery-2026-10-22` をプライベート リポジトリに保存します。
