# Собираем исходный код

Публичный артефакт — это исходный код, а не заранее созданный образ автономного устройства. Исходная сборка может загружать зависимости; установка с использованием подготовленного полного пакета остается в автономном режиме. Ни одному из процессов не требуется ни ViKey SDK, ни USB-ключ.

Для полной установки устройства начните с корневого [быстрого запуска](../../README.ru.md#install) и [установщика исходного кода](../../install/SOURCE-INSTALL.ru.md): `sudo bash install/from-source.sh` загружает, собирает, упаковывает и устанавливает на совместимом свежем Spark. Веб-сборка для разработки, представленная ниже, не является установщиком и не запускает полный продукт.

## Развитие

Используйте Node.js 24, pnpm 11.1.3 (см. корень `package.json`), Python 3.10+ и версию Go, объявленную в каждом `go.mod` (в настоящее время агент узла 1.26). На сборочной машине:

Экспорт исходного кода намеренно не имеет частной истории Git. Прежде чем запускать инструменты исходного кода для этого экспортированного дерева, инициализируйте свой собственный репозиторий и зафиксируйте проверенное дерево (`git init`, `git add .`, `git commit`). Обычный общедоступный клон Git не требует этого шага. Используйте этот новый коммит в качестве идентификатора сборки; не утверждайте, что экспортированное измененное дерево является старой фиксацией доставки.

```sh
pnpm install --frozen-lockfile
pnpm --filter @teamaibox/web build
python3 tools/open_source_inventory.py --check
```

Веб-сборка — это проверка компиляции, а не приемка продукта. Службы времени выполнения используют файлы Dockerfile в `deploy/`. Для выполнения DGX Spark требуется Linux ARM64 и существующая среда NVIDIA/Docker. Проверка исходного кода рабочего стола не является заменой этого оборудования. Не используйте сценарии исторических лабораторных исследований в качестве установщиков.

Помощникам сборки фабрики Python дополнительно требуется PyYAML; см. предварительную проверку зависимостей установщика. Никакого установленного диска с операционной системой или учетной записи разработчика не требуется.

## Исключены скомпилированные входные данные

Экспортер пропускает двоичные файлы, даже если их расширение выглядит безобидным:

- Соберите `services/node-agent` и его помощник `cmd/factory-worker-spec` из исходного кода Go; исполняемый файл корня репозитория `node-agent` не является исходным входом.
- APK-файлы Android-приложений и файлы подписи не поставляются. Их исходный код и манифесты под `tools/fixtures/` остаются доступными для локальных тестовых сборок.
- Текущая сборка кастинга устройств использует `deploy/appliance/wireless-casting-plugin.Dockerfile`. Ему не нужны старые архивы пакетов Alpine. Если вместо этого вы используете автономный плагин Dockerfile, получите точные пакеты, указанные в [его исходном манифесте контрольной суммы](../../apps/wireless-casting-plugin/vendor/alpine/security-update-20261010.json), и проверьте их значения SHA-256 перед сборкой. Никогда не заменяйте произвольный пакет, если закрепленный исходный артефакт недоступен.
- Браузерный модуль LiveKit и его лицензия остаются в общедоступном каталоге плагина; резервный архив npm `.tgz` не поставляется.

Это исключения распространения исходного кода, а не изменения работающего устройства.

## Полный офлайн-пакет

Начните с [конвейера с открытым исходным кодом](../../install/PUBLIC-BUILD.ru.md). Он предоставляет общедоступные родительские образы и зависимости времени выполнения, созданные в исходном коде; предыдущая установка разработчика не требуется. Исторические рецепты многоуровневых образов не являются отправной точкой для новой установки.

Следуйте [install/README.md](../../install/README.ru.md), чтобы узнать о сборках образов приложений, инструментах гостевого хоста, пакетах автономного хоста, сборе ресурсов и окончательной упаковке. Целевое устройство не извлекает зависимости и не заменяет Docker/NVIDIA. Установите входные данные сборки для фактического исходного коммита, идентификаторов контента ARM64 OCI и чистых путей к ресурсам. Никакого IP-адреса хоста разработки, учетной записи, сертификата или тома не требуется. Веса моделей и ресурсы гостевой/среды выполнения получаются отдельно из точных исходных источников, указанных в [comComponents.json](components.json), и блокировок репозитория. Сохраните свои лицензии и необходимые уведомления об источниках.

**Доступность исходного кода не является разрешением на бинарное распространение.** Текущий контракт на полный автономный пакет включает среду выполнения Google Android; свидетельством его частной установки не является разрешение на распространение GMS. Существующий упаковщик остается без изменений, но такой пакет не является одобренной общедоступной загрузкой, пока не будут получены соответствующие права. Публичная двоичная версия только для AOSP будет представлять собой отдельное изменение пакета, а не заменена здесь молча. ISO-файлы Windows/Linux предоставляются каждым пользователем; никакие установленные тестовые гости или состояния учетной записи не являются общедоступными входными данными сборки.
