# Граница конфиденциальности общедоступного источника

Публичный репозиторий продуктов — это новый снимок исходного кода, а не зеркало частной истории разработки. Маркетинговый веб-сайт имеет собственный частный репозиторий и не включен сюда.

## Удален материал

- Исправлены имена и пароли учетных записей для тестирования развертывания, а также списки личных учетных записей.
- Оболочки и сценарии развертывания/восстановления одного устройства, которые записывали исторические идентификаторы устройств или утверждали результаты на основе частных доказательств.
- Фактические адреса хостов, домашние каталоги, идентификаторы контейнеров/устройств и исторические снимки обслуживания. В сохраненных тестах используются явно синтетические приспособления; поддерживаемые оперативные инструменты требуют явных целевых входных данных.
- Гостевые диски, состояние входа в систему Android, сеансы браузера, установочные пакеты, веса моделей и частные доказательства находятся за пределами распространения общедоступных источников.

Частный архив и оригинальные бирки доставки остаются нетронутыми. Ничто в этой очистке источника не меняет учетные записи устройств, гостевые данные, работающие службы или развертывание веб-сайта. Заводские настройки по умолчанию `admin / admin` сохранены намеренно; это не частные учетные данные. Администраторы должны изменить его перед разоблачением.

## Обзор и проверка

Просмотрите как рабочее дерево, так и все доступные фиксации/теги в публикуемом репозитории. Используйте Gitleaks плюс `tools/open_source_sensitive.py`; ни один из них сам по себе не является доказательством отсутствия паролей с низкой энтропией или личных метаданных. Сравнивайте подтвержденные старые частные значения, используя частный внешний список запрещенных данных, а не зафиксированный тестовый прибор. Просмотрите оставшиеся результаты индивидуально, включая тестовые файлы.

Проверки очистки включают в себя проверку политики источника, синтетическую регрессию, проверку конфигурации и синтаксиса. Они не входят в систему, используя обнаруженные учетные данные, не переустанавливают коробку и не повторяют приемку продукта. Более раннее исправление упаковки API (включая общий источник пользовательского интерфейса и проверку точки входа только для импорта) остается в исходном коде.

Новые клоны не должны импортировать устаревшие коммиты, ссылки или теги. Удаление репозитория не приводит к отзыву копий, уже загруженных другими. Никакое сканирование не может установить, что неизвестные учетные данные никогда не копировались; учетные данные, которые фактически использовались, должны быть заменены их оператором. Эта очистка не претендует на то, чтобы повернуть ее.

См. [RELEASING.md](RELEASING.ru.md) для инструкций по экспорту исходного кода и проверке и [BUILDING.md](BUILDING.ru.md) для предварительных условий сборки и отдельно полученных ресурсов.
