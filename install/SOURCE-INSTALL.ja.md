# パブリック クローンからインストールする

このエントリ ポイントは、必要なパブリック入力を準備し、アプリケーション イメージを構築して、インストール前に完全なパッケージを生成します。ビルドの進行状況は再開可能です。最終的なインストール準備結果のみが、インストールされたアプライアンスを示します。ダウンロードまたはプリフライトの成功だけでは成功しません。

生成されたモデル、コンテナー イメージ、インストール パッケージ、テスト記録、および認証情報をリポジトリの外に保管します。サードパーティのミラーの可用性は保証されません。検証済みのポータブル キャッシュとオフライン パッケージについては以下で説明します。

Ubuntu 24.04 を搭載し、Docker/Compose、NVIDIA、KVM が動作している新しい DGX Spark で、パブリック リポジトリのクローンを作成し、そのルートから実行します。

```sh
git clone https://github.com/weerocksllc/teamaibox.git
cd teamaibox
sudo bash install/from-source.sh
```

上流のモデル/イメージ エンドポイントに到達できない中国本土のネットワークの場合は、地域のダウンロード ソースと同じエントリ ポイントを使用します。

```sh
sudo bash install/from-source.sh --region cn
```

これは、**オンライン ソース ビルドの後にオフライン インストール**を行うものであり、オフライン ソース ビルドではありません。不足しているビルド ツールを自動的に準備し、6 つのモデル入力をダウンロードし、Android とすべてのアプリケーション イメージをビルドしてアセンブルし、2 つのソース モデルを量子化し、ファームウェア/ホスト パッケージを収集し、完全なオフライン パッケージを作成して、既存のインストーラーを実行します。 Docker/NVIDIA の置き換え、Docker デーモンの再起動、既存のインストールのクリア、ホスト ルーティング、DNS、または VPN 設定の変更は行われません。モデル、ゲストのログイン状態、およびプライベート マーケティング Web サイトは、別のインストールから取得されません。

デフォルトのワークスペースは `/var/tmp/teamaibox-source-build` です。ダウンロード キャッシュとステージごとのログは、クローンの外部に存在します。インストールのデフォルトは `/srv/teamaibox/installation` です。大規模なダウンロードと数百 GB の一時ディスク使用量が予想されます。モデルの読み込みと GPU 量子化にはかなりの時間がかかる場合があります。固定された完了時間は約束されません。

## 中断後の再開と進行状況

中断された場合は、**まったく同じコマンドを再実行**してください。ワークスペースを維持します。実行中のビルドでは別のライターが除外されます。完成したステージファイルとイメージは再利用する前に検証されます。失敗した試行は引き続き診断に利用できますが、次の試行では失敗したステージのみが実行されます。モデルのバイト範囲と検証されたファイルは保持されます。 `state.json` は、現在のステージとそのログ ディレクトリを識別します。公式モデルのダウンロードでは、制限されたファイル/範囲の同時実行性が使用されます。地域のソースは保守的な同時実行を使用してレート制限を減らします。ファイルごとのバイト進捗レポートは、最終的なパブリッシャー ハッシュ検証とは別に、転送または再利用された範囲をレポートします。ゲストツールのコンパイルは、ログイン ホームのないシステム サービスでも機能します。結果として得られるインストール アセットの外側に分離されたビルド キャッシュが作成されます。

ソースの変更には新しい `--work-dir` が必要です。 `--cache-dir /path/to/public-cache` でダウンロード キャッシュを再利用します。ソース フィンガープリントは、異なるコードからの出力をサイレントに組み合わせるのを防ぎます。既存のインストールは、リセットを促すものではありません。再開できるのは、このワークスペースの同じパッケージのインストールだけです。他のインストールでは、アップグレード プロセスを使用する必要があります。

便利なモード:

```sh
sudo bash install/from-source.sh --check
sudo bash install/from-source.sh --region cn --download-models-only
sudo bash install/from-source.sh --region cn --build-only
```

`--check` は読み取り専用であり、ダウンロードが成功するとは主張しません。ダウンロード専用とビルド専用は、インストールの準備が整っていることを明示的に主張しません。

## 地域別のダウンロード元とデータ整合性

中国モードでは、モデル転送に `https://hf-mirror.com` を使用し、ダイジェスト固定された Docker Hub 入力に `https://docker.m.daocloud.io` を使用します。これらはサードパーティのミラーであり、Weerocks またはモデル発行者が運営するサービスではありません。モデルの Git コミットは製品プロファイルによって固定されます。検証された Git ツリーと LFS ポインターにより、予想されるファイル サイズとハッシュが確立されます。ミラーの API 応答だけでは信頼を確立できません。 Docker は固定されたマニフェスト/レイヤー ダイジェストを検証します。固定されていないタグは自動的にリダイレクトされません (Go ビルド ツールには明示的なダイジェスト ロックがあります)。 NVIDIA のイメージは発行者のレジストリに残ります。 TLS 検証は有効のままであり、アカウント トークンはモデル ミラーに送信されません。

`--model-endpoint` and `--registry-mirror` を使用して独自の HTTPS オリジンを選択できます。エンドポイント値には、認証情報やクエリ パラメータを含めることはできません。スコープ付き Docker ラッパーは、システム デーモンや他のプロジェクトではなく、このビルド プロセスにのみ適用されます。 SDK メタデータとライセンス アーカイブは引き続き、権威ある HTTPS 発行者から提供されます。ミラーはハッシュを作成できません。

ミラーはレートが制限されているか、使用できない場合があります。モデルのダウンロードは制限付き同時実行で実行され、クールダウンが考慮されます。すべてのネットワーク上のすべてのアップストリームへの接続を保証できるスクリプトはありません。両方のルートが利用できない場合は、アクセス可能な互換性のあるマシン上にダウンロードまたは完全なパッケージを準備し、それらをコピーします。

- `--download-models-only --cache-dir <public-cache>` は、検証済みのモデル ファイルと再開可能なキャッシュを準備します。そのディレクトリをコピーし、ターゲット上で `--cache-dir` を使用して渡します。再利用されたすべてのモデルは、固定された ID と照合してチェックされます。このキャッシュは完全なオフライン インストール パッケージではありません。
- `--build-only` は、オフライン インストール用の完全なパッケージを準備します。 tar とチェックサムをコピーし、検証して解凍し、その中で `sudo ./install.sh` を実行します。これは、信頼できる切断されたホストのルートです。ターゲット上の VPN や開発ボックスへのアクセスは必要ありません。

パブリック入力の代わりに、ライブ Docker データ ディレクトリ、ゲスト ディスク、ブラウザ プロファイル、アカウント データベース、資格情報、またはプライベート キャッシュをコピーしないでください。チェックサムを無効にしたり、ログイン/チャレンジ ページをモデル ファイルとして受け入れたりしないでください。

## ライセンスと初回使用

ビルドする前に、`THIRD_PARTY_NOTICES.md`、Android SDK の規約、および個々のモデルのライセンスを確認してください。サードパーティのコンポーネントをダウンロードしても、それが MIT アセットに変換されたり、Google の認定/再配布の権利が付与されたりすることはありません。 Windows/Linux ISO メディアは引き続きユーザーが提供します。工場出荷時のログインは `admin/admin` のままです。アプライアンスを露出する前に変更してください。既存のインストーラーは、独立したサービス資格情報を生成し、実際の準備状況を報告します。

完了したら、同じ LAN 上で `https://<BOX_LAN_IP>/` を開きます。 Docker ブリッジや VPN アドレスではなく、Spark の現在の物理ネットワーク アドレスを置き換えます。ソース ワークスペースの `state.json` はビルドの進行状況を記録します。インストールされた `/srv/teamaibox/installation/readiness.json` はインストール チェックを記録します。コンパイルの成功も、リスニング コンテナーのヘルス チェックも、アプリケーションの目に見えるエンドツーエンドの操作に代わるものではありません。

キャスト ランタイムには、UxPlay レシーバー、プライベート D-Bus および Avahi Discovery 実行可能ファイル、およびそのメディア プラグインが含まれている必要があります。最終的なパブリック イメージのビルドでは、これらの実行可能ファイルがチェックされます。クライアント ライブラリだけでは不十分です。新規インストールでは、デスクトップ プロキシとゲートウェイを他の API ネットワーク名前空間に依存するものに登録するため、グループ化された API アップグレードでデスクトップ接続パスを保持できます。メンテナンス中にそのグループのサブセットのみを再作成しないでください。
