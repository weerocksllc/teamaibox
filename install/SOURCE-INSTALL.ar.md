# التثبيت من نسخة عامة

تقوم نقطة الإدخال هذه بإعداد المدخلات العامة المطلوبة وإنشاء صور التطبيق وإنتاج حزمة كاملة قبل تثبيته. تقدم البناء قابل للاستئناف؛ تشير نتيجة جاهزية التثبيت النهائية فقط إلى وجود جهاز مثبت. لا ينجح التنزيل أو الاختبار المبدئي وحده.

احتفظ بالنماذج التي تم إنشاؤها وصور الحاويات وحزم التثبيت وسجلات الاختبار وبيانات الاعتماد خارج المستودع. توافر مرآة الطرف الثالث غير مضمون؛ يتم وصف ذاكرة التخزين المؤقت المحمولة والحزم غير المتصلة بالإنترنت التي تم التحقق منها أدناه.

على DGX Spark جديد مع Ubuntu 24.04، يعمل Docker/Compose وNVIDIA وKVM، على استنساخ المستودع العام وتشغيله من جذره:

```sh
git clone https://github.com/weerocksllc/teamaibox.git
cd teamaibox
sudo bash install/from-source.sh
```

بالنسبة لشبكة البر الرئيسي للصين حيث لا يمكن الوصول إلى نقاط نهاية النموذج/الصورة الأولية، استخدم نفس نقطة الإدخال مع مصادر التنزيل الإقليمية:

```sh
sudo bash install/from-source.sh --region cn
```

هذا **إنشاء مصدر عبر الإنترنت يتبعه تثبيت دون اتصال**، وليس إنشاء مصدر دون اتصال. يقوم تلقائيًا بإعداد أدوات البناء المفقودة، وتنزيل مدخلات النماذج الستة، وإنشاء وتجميع Android وجميع صور التطبيقات، وتحديد حجم نموذجي المصدر، وجمع حزم البرامج الثابتة/المضيف، وإنشاء الحزمة الكاملة غير المتصلة بالإنترنت وتشغيل برنامج التثبيت الحالي الخاص به. ولا يحل محل Docker/NVIDIA، أو إعادة تشغيل البرنامج الخفي Docker، أو مسح تثبيت موجود، أو تغيير توجيه المضيف، أو إعدادات DNS أو VPN. لا يتم أخذ النماذج وحالات تسجيل دخول الضيف وموقع التسويق الخاص من تثبيت آخر.

مساحة العمل الافتراضية هي `/var/tmp/teamaibox-source-build`؛ توجد ذاكرة التخزين المؤقت للتنزيل والسجلات لكل مرحلة هناك، خارج النسخة. التثبيت الافتراضي هو `/srv/teamaibox/installation`. توقع تنزيلات كبيرة وعدة مئات من الجيجابايت من الاستخدام المؤقت للقرص. يمكن أن يستغرق تحميل النموذج وتكميم وحدة معالجة الرسومات وقتًا طويلاً؛ لم يتم الوعد بوقت إكمال ثابت.

## استئناف التثبيت وحالته

في حالة المقاطعة، **أعد تشغيل نفس الأمر بالضبط**. احتفظ بمساحة العمل. البنية قيد التشغيل تستثني كاتبًا آخر؛ يتم التحقق من ملفات وصور المرحلة المكتملة قبل إعادة استخدامها. تظل المحاولات الفاشلة متاحة للتشخيص، في حين أن المحاولة التالية تستمر فقط في المرحلة الفاشلة. يتم الاحتفاظ بنطاقات البايت النموذجية والملفات التي تم التحقق منها. يحدد `state.json` المرحلة الحالية ودليل السجل الخاص بها. تستخدم تنزيلات النموذج الرسمي تزامن الملف/النطاق المحدود؛ تستخدم المصادر الإقليمية التزامن المحافظ لتقليل الحد من المعدل. يتم نقل تقارير تقدم البايت لكل ملف أو إعادة استخدامها بشكل منفصل عن التحقق من تجزئة الناشر النهائي. يعمل تجميع أداة الضيف أيضًا ضمن خدمة النظام دون تسجيل الدخول إلى المنزل: فهو ينشئ ذاكرة تخزين مؤقت معزولة خارج أصول التثبيت الناتجة.

تتطلب تغييرات المصدر `--work-dir` جديد؛ أعد استخدام ذاكرة التخزين المؤقت للتنزيل مع `--cache-dir /path/to/public-cache`. تمنع بصمة المصدر دمج المخرجات من تعليمات برمجية مختلفة بصمت. التثبيت الموجود ليس دعوة لإعادة تعيينه: يمكن فقط استئناف تثبيت نفس الحزمة لمساحة العمل هذه؛ يجب أن تستخدم عمليات التثبيت الأخرى عملية الترقية الخاصة بها.

أوضاع مفيدة:

```sh
sudo bash install/from-source.sh --check
sudo bash install/from-source.sh --region cn --download-models-only
sudo bash install/from-source.sh --region cn --build-only
```

`--check` للقراءة فقط ولا يدعي أن التنزيلات ستنجح. لا يطالب التنزيل فقط والإنشاء فقط صراحةً بجاهزية التثبيت.

## مصادر التنزيل الإقليمية والتحقق من سلامة الملفات

يستخدم الوضع الصيني `https://hf-mirror.com` لنقل النموذج و`https://docker.m.daocloud.io` لمدخلات Docker Hub المثبتة. هذه مرايا تابعة لجهات خارجية، وليست خدمات تديرها Weerocks أو الناشرين النموذجيين. يتم تثبيت نموذج التزام Git بواسطة ملف تعريف المنتج؛ تحدد شجرة Git ومؤشرات LFS التي تم التحقق منها أحجام الملفات والتجزئة المتوقعة. لا يمكن لاستجابة واجهة برمجة تطبيقات المرآة وحدها إنشاء الثقة. يتحقق Docker من ملخصات البيان/الطبقة المثبتة. لا تتم إعادة توجيه العلامات غير المثبتة تلقائيًا (تحتوي أداة إنشاء Go على قفل ملخص صريح). تظل صور NVIDIA موجودة في سجل الناشر الخاص بها. يظل التحقق من TLS ممكنًا ولا يتم إرسال أي رموز مميزة للحساب إلى مرايا النماذج.

يمكنك تحديد أصول HTTPS الخاصة بك باستخدام `--model-endpoint` and `--registry-mirror`. يجب ألا تتضمن قيم نقطة النهاية بيانات اعتماد أو معلمات استعلام. ينطبق غلاف Docker ذو النطاق فقط على عملية البناء هذه، وليس البرنامج الخفي للنظام أو المشاريع الأخرى. لا تزال بيانات تعريف SDK وأرشيفات الترخيص تأتي من ناشري HTTPS المعتمدين لديهم؛ لا يمكن للمرآة أن تخترع التجزئة.

يمكن أن تكون المرايا محدودة السعر أو غير متوفرة. يتم تشغيل تنزيلات النماذج بتزامن محدود وتحترم فترات التهدئة. لا يوجد برنامج نصي يمكنه ضمان الاتصال بكل المنبع على كل شبكة. إذا لم يكن كلا المسارين متاحين، فقم بإعداد التنزيلات أو الحزمة الكاملة على جهاز متوافق يمكن الوصول إليه وانسخها على:

- يقوم `--download-models-only --cache-dir <public-cache>` بإعداد ملفات النماذج التي تم التحقق منها وذاكرة التخزين المؤقت القابلة للاستئناف. انسخ هذا الدليل، ثم مرره مع `--cache-dir` على الهدف. يتم فحص كل نموذج مُعاد استخدامه مقابل هويته المثبتة. ذاكرة التخزين المؤقت هذه ** ليست ** حزمة تثبيت كاملة دون اتصال بالإنترنت.
- يقوم `--build-only` بإعداد الحزمة الكاملة للتثبيت دون اتصال بالإنترنت. انسخ القطران والمجموع الاختباري الخاص به، وتحقق منه وأخرجه، ثم قم بتشغيل `sudo ./install.sh` بداخله. هذا هو مسار المضيف المنفصل الموثوق به؛ لا يتطلب VPN على الهدف أو الوصول إلى مربع التطوير.

لا تقم مطلقًا بنسخ دليل بيانات Docker المباشر أو أقراص الضيف أو ملفات تعريف المتصفح أو قواعد بيانات الحساب أو بيانات الاعتماد أو ذاكرات التخزين المؤقت الخاصة كبديل للمدخلات العامة. لا تقم بتعطيل المجاميع الاختبارية أو قبول صفحة تسجيل الدخول/التحدي كملف نموذجي.

## الترخيص والاستخدام الأول

راجع `THIRD_PARTY_NOTICES.md`، وشروط Android SDK وتراخيص النماذج الفردية قبل الإنشاء. لا يؤدي تنزيل مكونات الجهات الخارجية إلى تحويلها إلى أصول MIT أو منح Google حقوق التصديق/إعادة التوزيع. لا تزال وسائط Windows/Linux ISO مقدمة من قبل المستخدم. يظل تسجيل دخول المصنع `admin/admin`؛ قم بتغييره قبل تعريض الجهاز. يقوم المثبت الحالي بإنشاء بيانات اعتماد خدمة مستقلة ويبلغ عن الاستعداد الفعلي.

بعد الانتهاء، افتح `https://<BOX_LAN_IP>/` على نفس الشبكة المحلية (LAN)؛ استبدل عنوان الشبكة الفعلية الحالي لـ Spark، وليس عنوان Docker Bridge أو VPN. تعمل سجلات `state.json` الخاصة بمساحة العمل المصدر على إنشاء التقدم. يسجل `/srv/teamaibox/installation/readiness.json` المثبت عمليات التحقق من التثبيت. لا يحل التحويل البرمجي الناجح ولا التحقق من صحة حاوية الاستماع محل التشغيل المرئي من طرف إلى طرف للتطبيق.

يجب أن يحتوي وقت تشغيل الإرسال على جهاز استقبال UxPlay والملفات التنفيذية الخاصة باكتشاف D-Bus وAvahi بالإضافة إلى المكونات الإضافية للوسائط. يتحقق إنشاء الصورة العامة النهائية من هذه الملفات التنفيذية؛ مكتبة العميل وحدها غير كافية. يقوم التثبيت الجديد بتسجيل وكيل سطح المكتب والبوابة مع الجهات الأخرى التابعة لمساحة اسم شبكة واجهة برمجة التطبيقات (API) حتى تتمكن ترقيات واجهة برمجة التطبيقات (API) المجمعة من الاحتفاظ بمسار اتصال سطح المكتب. لا تقم بإعادة إنشاء مجموعة فرعية فقط من تلك المجموعة أثناء الصيانة.
