# ติดตั้งจากโคลนสาธารณะ

จุดเริ่มต้นนี้จะเตรียมอินพุตสาธารณะที่จำเป็น สร้างอิมเมจแอปพลิเคชัน และสร้างแพ็คเกจที่สมบูรณ์ก่อนทำการติดตั้ง ความคืบหน้าของการสร้างสามารถดำเนินการต่อได้ เฉพาะผลความพร้อมในการติดตั้งขั้นสุดท้ายเท่านั้นที่บ่งชี้ถึงอุปกรณ์ที่ติดตั้ง ความสำเร็จในการดาวน์โหลดหรือ preflight เพียงอย่างเดียวไม่สามารถทำได้

เก็บโมเดลที่สร้างขึ้น อิมเมจคอนเทนเนอร์ แพ็คเกจการติดตั้ง บันทึกการทดสอบ และข้อมูลประจำตัวไว้นอกพื้นที่เก็บข้อมูล ไม่รับประกันความพร้อมใช้งานของมิเรอร์ของบุคคลที่สาม แคชแบบพกพาที่ตรวจสอบแล้วและแพ็คเกจออฟไลน์มีอธิบายไว้ด้านล่าง

บน DGX Spark ใหม่ด้วย Ubuntu 24.04 ที่ใช้งาน Docker/Compose, NVIDIA และ KVM โคลนพื้นที่เก็บข้อมูลสาธารณะและเรียกใช้จากราก:

```sh
git clone https://github.com/weerocksllc/teamaibox.git
cd teamaibox
sudo bash install/from-source.sh
```

สำหรับเครือข่ายจีนแผ่นดินใหญ่ที่ไม่สามารถเข้าถึงจุดสิ้นสุดโมเดล/รูปภาพอัปสตรีมได้ ให้ใช้จุดเริ่มต้นเดียวกันกับแหล่งดาวน์โหลดระดับภูมิภาค:

```sh
sudo bash install/from-source.sh --region cn
```

นี่คือ **บิลด์ซอร์สออนไลน์ตามด้วยการติดตั้งออฟไลน์** ไม่ใช่บิลด์ซอร์สออฟไลน์ โดยจะเตรียมเครื่องมือบิลด์ที่ขาดหายไปโดยอัตโนมัติ ดาวน์โหลดอินพุตโมเดลทั้ง 6 รายการ สร้างและประกอบ Android และอิมเมจแอปพลิเคชันทั้งหมด วัดปริมาณโมเดลแหล่งที่มาทั้งสอง รวบรวมแพ็คเกจเฟิร์มแวร์/โฮสต์ สร้างแพ็คเกจออฟไลน์ที่สมบูรณ์ และรันโปรแกรมติดตั้งที่มีอยู่ ไม่ได้แทนที่ Docker/NVIDIA รีสตาร์ท Docker daemon ล้างการติดตั้งที่มีอยู่ หรือเปลี่ยนการกำหนดเส้นทางโฮสต์ การตั้งค่า DNS หรือ VPN โมเดล สถานะการเข้าสู่ระบบของผู้เยี่ยมชม และเว็บไซต์การตลาดส่วนตัวไม่ได้นำมาจากการติดตั้งอื่น

พื้นที่ทำงานเริ่มต้นคือ `/var/tmp/teamaibox-source-build`; ดาวน์โหลดแคชและบันทึกต่อขั้นตอนอยู่ที่นั่น นอกโคลน การติดตั้งเริ่มต้นที่ `/srv/teamaibox/installation` คาดว่าจะมีการดาวน์โหลดจำนวนมากและการใช้งานดิสก์ชั่วคราวหลายร้อย GB การโหลดโมเดลและการหาปริมาณ GPU อาจใช้เวลานานมาก ไม่มีสัญญาเวลาเสร็จสิ้นที่แน่นอน

## การติดตั้งต่อและตรวจสอบสถานะ

หากถูกขัดจังหวะ **ให้รันคำสั่งเดิมอีกครั้ง** เก็บพื้นที่ทำงาน. บิลด์ที่รันอยู่จะไม่รวมตัวเขียนอื่น ไฟล์และรูปภาพบนเวทีที่เสร็จสมบูรณ์ได้รับการตรวจสอบก่อนนำมาใช้ซ้ำ ความพยายามที่ล้มเหลวยังคงพร้อมสำหรับการวินิจฉัย ในขณะที่ความพยายามครั้งต่อไปจะรันเฉพาะระยะที่ล้มเหลวเท่านั้น ช่วงไบต์ของโมเดลและไฟล์ที่ตรวจสอบแล้วจะยังคงอยู่ `state.json` ระบุระยะปัจจุบันและไดเร็กทอรีบันทึก การดาวน์โหลดโมเดลอย่างเป็นทางการใช้ไฟล์/ขอบเขตการทำงานพร้อมกัน แหล่งข้อมูลระดับภูมิภาคใช้การดำเนินการพร้อมกันแบบอนุรักษ์นิยมเพื่อลดการจำกัดอัตรา รายงานความคืบหน้าของไบต์ต่อไฟล์ที่ถ่ายโอนหรือนำมาใช้ซ้ำโดยแยกจากการตรวจสอบแฮชของผู้เผยแพร่ขั้นสุดท้าย การคอมไพล์เครื่องมือผู้เยี่ยมชมยังทำงานภายใต้บริการระบบที่ไม่มีการเข้าสู่ระบบที่บ้าน: สร้างแคชบิลด์แบบแยกส่วนภายนอกสินทรัพย์การติดตั้งที่เป็นผลลัพธ์

การเปลี่ยนแปลงแหล่งที่มาจำเป็นต้องมี `--work-dir` ใหม่ ใช้แคชดาวน์โหลดซ้ำด้วย `--cache-dir /path/to/public-cache` ลายนิ้วมือต้นทางจะป้องกันไม่ให้รวมเอาต์พุตจากโค้ดที่แตกต่างกันอย่างเงียบๆ การติดตั้งที่มีอยู่ไม่ใช่คำเชิญให้รีเซ็ต: เฉพาะการติดตั้งแพ็คเกจเดียวกันของพื้นที่ทำงานนี้เท่านั้นที่สามารถดำเนินการต่อได้ การติดตั้งอื่นๆ ต้องใช้กระบวนการอัปเกรด

โหมดที่มีประโยชน์:

```sh
sudo bash install/from-source.sh --check
sudo bash install/from-source.sh --region cn --download-models-only
sudo bash install/from-source.sh --region cn --build-only
```

`--check` เป็นแบบอ่านอย่างเดียวและไม่อ้างว่าการดาวน์โหลดจะสำเร็จ ดาวน์โหลดอย่างเดียวและสร้างอย่างเดียวอย่างชัดเจนไม่ได้อ้างสิทธิ์ความพร้อมในการติดตั้ง

## แหล่งที่มาและความซื่อสัตย์ระดับภูมิภาค

โหมดจีนใช้ `https://hf-mirror.com` สำหรับการถ่ายโอนโมเดลและ `https://docker.m.daocloud.io` สำหรับอินพุต Docker Hub ที่ปักหมุดแยกย่อย สิ่งเหล่านี้เป็นมิเรอร์ของบุคคลที่สาม ไม่ใช่บริการที่ดำเนินการโดย Weerocks หรือผู้เผยแพร่โมเดล โมเดล Git คอมมิตถูกปักหมุดโดยโปรไฟล์ผลิตภัณฑ์ แผนผัง Git และตัวชี้ LFS ที่ได้รับการตรวจสอบแล้วจะสร้างขนาดไฟล์และแฮชที่คาดหวัง การตอบสนอง API ของมิเรอร์เพียงอย่างเดียวไม่สามารถสร้างความน่าเชื่อถือได้ นักเทียบท่าตรวจสอบรายการ / การย่อยเลเยอร์ที่ปักหมุดไว้ แท็กที่เลิกปักหมุดจะไม่เปลี่ยนเส้นทางโดยอัตโนมัติ (เครื่องมือ Go build มีการล็อกไดเจสต์อย่างชัดเจน) รูปภาพ NVIDIA ยังคงอยู่ในรีจิสทรีของผู้จัดพิมพ์ การตรวจสอบ TLS ยังคงเปิดใช้งานอยู่ และไม่มีการส่งโทเค็นบัญชีไปยังโมเดลมิเรอร์

คุณสามารถเลือกต้นทาง HTTPS ของคุณเองได้โดยใช้ `--model-endpoint` and `--registry-mirror` ค่าปลายทางต้องไม่มีข้อมูลรับรองหรือพารามิเตอร์การค้นหา Wrapper Docker ที่มีการกำหนดขอบเขตจะนำไปใช้กับกระบวนการบิลด์นี้เท่านั้น ไม่ใช่ System Daemon หรือโปรเจ็กต์อื่น ข้อมูลเมตา SDK และคลังใบอนุญาตยังคงมาจากผู้เผยแพร่ HTTPS ที่น่าเชื่อถือ กระจกไม่สามารถสร้างแฮชได้

กระจกเงาอาจมีการจำกัดอัตราหรือไม่มีจำหน่าย การดาวน์โหลดโมเดลจะดำเนินการพร้อมกันแบบมีขอบเขตและคำนึงถึงคูลดาวน์ ไม่มีสคริปต์ใดรับประกันการเชื่อมต่อกับทุกอัปสตรีมบนทุกเครือข่าย หากทั้งสองเส้นทางไม่พร้อมใช้งาน ให้เตรียมการดาวน์โหลดหรือแพ็คเกจทั้งหมดบนเครื่องที่ใช้งานร่วมกันได้และคัดลอกไปที่:

- `--download-models-only --cache-dir <public-cache>` เตรียมไฟล์โมเดลที่ได้รับการยืนยันและแคชที่ดำเนินการต่อได้ คัดลอกไดเร็กทอรีนั้น จากนั้นส่งต่อโดยมี `--cache-dir` บนเป้าหมาย โมเดลที่นำกลับมาใช้ใหม่ทุกชิ้นจะได้รับการตรวจสอบโดยเทียบกับข้อมูลประจำตัวที่ปักหมุดไว้ แคชนี้ **ไม่ใช่** แพ็คเกจการติดตั้งออฟไลน์แบบเต็ม
- `--build-only` เตรียมแพ็คเกจเต็มสำหรับการติดตั้งแบบออฟไลน์ คัดลอก tar และเช็คซัม ตรวจสอบและแตกไฟล์ จากนั้นรัน `sudo ./install.sh` ข้างใน นี่คือเส้นทางโฮสต์ที่ไม่ได้เชื่อมต่อที่เชื่อถือได้ ไม่จำเป็นต้องมี VPN บนเป้าหมายหรือเข้าถึงกล่องการพัฒนา

ห้ามคัดลอกไดเร็กทอรีข้อมูล Docker, ดิสก์สำหรับแขก, โปรไฟล์เบราว์เซอร์, ฐานข้อมูลบัญชี, ข้อมูลรับรอง หรือแคชส่วนตัวเพื่อทดแทนอินพุตสาธารณะ อย่าปิดการใช้งานเช็คซัมหรือยอมรับหน้าเข้าสู่ระบบ/การท้าทายเป็นไฟล์โมเดล

## การอนุญาตและการใช้งานครั้งแรก

ตรวจสอบ `THIRD_PARTY_NOTICES.md` ข้อกำหนด Android SDK และใบอนุญาตแต่ละรุ่นก่อนสร้าง การดาวน์โหลดคอมโพเนนต์ของบุคคลที่สามไม่ได้เปลี่ยนให้เป็นเนื้อหา MIT หรือให้สิทธิ์การรับรอง/การแจกจ่ายซ้ำของ Google สื่อ ISO ของ Windows/Linux ยังคงให้โดยผู้ใช้ การเข้าสู่ระบบจากโรงงานยังคงอยู่ `admin/admin`; เปลี่ยนก่อนที่จะเปิดเผยเครื่อง โปรแกรมติดตั้งที่มีอยู่จะสร้างข้อมูลรับรองบริการอิสระและรายงานความพร้อมตามจริง

หลังจากเสร็จสิ้น ให้เปิด `https://<BOX_LAN_IP>/` บน LAN เดียวกัน แทนที่ที่อยู่เครือข่ายทางกายภาพปัจจุบันของ Spark ไม่ใช่สะพาน Docker หรือที่อยู่ VPN ความคืบหน้าในการสร้างระเบียน `state.json` ของพื้นที่ทำงานต้นทาง `/srv/teamaibox/installation/readiness.json` ที่ติดตั้งจะบันทึกการตรวจสอบการติดตั้ง การคอมไพล์ที่ประสบความสำเร็จหรือการตรวจสอบสถานภาพคอนเทนเนอร์การฟังไม่สามารถทดแทนการดำเนินการตั้งแต่ต้นทางถึงปลายทางที่มองเห็นได้ของแอปพลิเคชัน

รันไทม์การแคสต์ต้องมีตัวรับ UxPlay, โปรแกรมปฏิบัติการ D-Bus ส่วนตัวและการค้นพบ Avahi รวมถึงปลั๊กอินสื่อ การสร้างอิมเมจสาธารณะขั้นสุดท้ายจะตรวจสอบไฟล์ปฏิบัติการเหล่านี้ ไลบรารีไคลเอนต์เพียงอย่างเดียวไม่เพียงพอ การติดตั้งใหม่จะลงทะเบียนพร็อกซีเดสก์ท็อปและเกตเวย์กับเนมสเปซเครือข่าย API อื่นๆ เพื่อให้การอัปเกรด API ที่จัดกลุ่มสามารถรักษาเส้นทางการเชื่อมต่อเดสก์ท็อปไว้ได้ อย่าสร้างเฉพาะชุดย่อยของกลุ่มนั้นใหม่ในระหว่างการบำรุงรักษา
