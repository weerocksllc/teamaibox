# Team AI Box أدوات الحزمة غير المتصلة بالإنترنت

المثبت الأصلي مرخص بـ MIT. تتضمن الحزم ترخيص الجذر ومخزون الطرف الثالث ونصوص الترخيص في مخزون تجزئة الملفات الخاصة بهم. لا يؤدي هذا إلى إعادة ترخيص النماذج أو خدمات Google أو برامج التشغيل أو تبعيات الحاوية باسم MIT. اقرأ [حدود الإصدار](../docs/open-source/RELEASING.ar.md) قبل التوزيع؛ لا تتمتع حزمة الاختبار الكاملة الحالية بتصريح إعادة التوزيع تلقائيًا.

يقوم العملاء بتشغيل **`sudo ./install.sh` داخل الحزمة المعدة**. يقوم المشرفون بإنشاء هذه الحزمة باستخدام `build-package.sh`. لا يحتاج العملاء غير المتصلين بالإنترنت إلى مستودعات الحزم Git أو Node أو Go أو pip أو العامة.

للتنزيل التلقائي والإنشاء والتثبيت من نسخة عامة، قم بتشغيل `sudo bash install/from-source.sh`. يمكن للشبكات في الصين استخدام `--region cn`. راجع [SOURCE-INSTALL.md](SOURCE-INSTALL.ar.md) للتشغيل والاستئناف والنقل دون اتصال. السيرة الذاتية مدعومة. فقط نتيجة الاستعداد النهائية تحدد اكتمال التثبيت. لا يكفي الاختبار المبدئي أو التنزيل الناجح.

الهدف هو DGX Spark جديد بنظام Ubuntu 24.04 ARM64 الخاص بالمصنع ومحرك Docker Engine وCompose v2 وNVIDIA Container Toolkit/GPU وKVM. لا يقوم المثبت باستبدال Docker/NVIDIA، أو إعادة تشغيل Docker، أو نسخ حسابات جهاز التطوير أو قاعدة البيانات أو المفاتيح أو الأجهزة الافتراضية.

> تبقى سجلات قبول التثبيت الخاصة في مستودع التطوير التاريخي. فهي ليست ملفات مصدر عام ولا بناء مدخلات. لا تتم إعادة تشغيل أدلة التثبيت الأول والاستئناف واسترداد التمهيد الموجودة لمجرد نشر المصدر، ولا تؤهل الصور العشوائية المنشأة حديثًا أو تمنح حقوق إعادة التوزيع لثنائيات الجهات الخارجية.

## المشرفون: إعداد مدخلات الإصدار

**للحصول على إصدار GitHub عام جديد، ابدأ بـ [PUBLIC-BUILD.md](PUBLIC-BUILD.ar.md).** يغطي الصور العامة وأوقات تشغيل الكاميرا وتنزيلات/تقدير النماذج والبرامج الثابتة دون الحاجة إلى صور من جهاز تطوير. تدعم مساعدات الصور ذات الطبقات أدناه التحديثات المتزايدة للعناصر التي تم التحقق منها؛ فهي ليست شروطًا أساسية لبناء جديد.

قد يستخدم التحضير الإنترنت. التثبيت من الحزمة التي تم تسليمها يجب ألا يؤدي إلى تنزيل التبعيات. يحتاج مضيف الحزمة إلى Python 3.10+ وPyYAML وGit وDocker و`dpkg-deb` ومساحة تخزين كافية. يمكن أن تكون النماذج والصور كبيرة الحجم؛ يحتفظ المحزم بكل من الشجرة المستخرجة و`.tar`، ويقدر المساحة من المدخلات الفعلية. فهو لا يقوم بمسح جهاز تطوير كامل ولا يصدر طبقات قابلة للكتابة من الحاويات الجاري تشغيلها.

1. قم بإعداد صور ARM64 من **إصدار إصدار واحد** لجميع الأدوار المطلوبة. استخدم نقاط إدخال البناء ضمن `deploy/images/`, `deploy/appliance/` وأدلة الضيف/النموذج المقابلة. يجب أن تدعم واجهة برمجة تطبيقات النظام الأساسي ووكيل العقدة والمجدول ووحدة تحكم الوكيل معرفات الصور المحلية؛ يجب أن تحتوي صورة PostgreSQL على بيان الترحيل الحالي، بما في ذلك الترحيل 116. ولا يقوم المحزم بتجميع صورة قديمة عشوائية إلى صورة حالية. مع الصور الأصلية التي تم التحقق منها من نفس الإصدار، استخدم `build_runtime_images.py --bases … --node-agent-binary … --output …` لإنشاء الصور الخمس اللاحقة. `--bases` عبارة عن خريطة معرف دور إلى صورة كاملة JSON. قم أولاً ببناء Node Agent باستخدام `GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build`. يمنع هذا المساعد عمليات السحب/إنشاء الشبكة، ويسجل هويات الأصل/المصدر، وينشئ صورًا جديدة دون نشر العلامات المباشرة أو تغييرها. تحتاج أقراص Android ROM النظيفة أيضًا إلى محول شبكة التحكم الحالي. استخدم `build_phone_images.py --bases <phone-role-image-ids.json> --output <new-directory>` لإضافة `phone_network.py` إلى كلتا الطبقتين اللاحقتين لـ ROM دون الوصول إلى الشبكة أو تغييرات بيانات ROM. يسجل معرفات الصور الدقيقة وملخصات المصدر. قم بربط ملف Android الجانبي بكلا المعرفين الجديدين، وليس المعرفين السابقين. أنشئ الويب وتسعة تطبيقات رسمية باستخدام `build_application_images.py --node-base <clean-arm64-node-image-id> --guacamole-image <offline-guacamole-image-id> --output <new-directory>`. قم أولاً ببناء الويب كما هو محدد بواسطة `apps/web/package.json`. يستخدم المساعد ملفات Dockerfiles للإنتاج، ويصلح دليل الويب في `/opt/teamaibox/web`، ويقارن ملفات الصور بتجزئة مدخلات البناء الحالية. لا تفترض أن صورة حاوية التطوير هي بنية ويب كاملة: فقد تعتمد على متغيرات دليل ثابت إضافية أو تحتوي على دليل قديم. لا يتم نشر هذا المساعد دون اتصال. ضع جميع معرفات الصور العشرة الجديدة في مدخلات الإصدار.
2. قم بتجميع أدلة كاملة ونظيفة لستة نماذج: التكوين، والأجزاء، والرموز المميزة، والتعليمات البرمجية والتراخيص المطلوبة. قم أيضًا بإعداد صورتين نظيفتين لنظام Android، UEFI `CODE.fd`/`VARS.fd`, `virtio.iso` والبرامج النصية لوقت تشغيل الرسم. لا تجمع أدلة مثيلات الهاتف، أو أقراص المستخدم، أو حالة تسجيل الدخول إلى Google، أو ملفات ISO الخاصة بالمستخدم، أو بيانات الاعتماد العالمية. ذاكرة القراءة فقط لنظام Android موجودة بالفعل داخل `phone-runtime` / `phone-google-runtime`؛ لا تقم بنسخ القرص الثاني. تحتوي أدلة الأصول `android-standard` / `android-google` فقط على المصدر والتراخيص و`manifest.json`: `schemaVersion: 1`, `androidVersion: "17"`, `baseBuildId: "16102939"`, `systemFamily: "standard"` or `"google-play"` و`runtimeImageId: "sha256:…"`. يجب أن يتطابق المعرف مع صورة وقت التشغيل المصدرة. يحتوي دليل برنامج التشغيل على `virtio.iso` فقط؛ تم رفض دليل التطوير الذي يحتوي أيضًا على `windows.iso`.
3. قم ببناء أداتي مضيف Linux ARM64 المجمعتين دون تثبيتهما على مضيف البناء:

   ```sh
   python3 install/build_guest_tools.py --output /build/artifacts/guest-host-tools
   ```

4. على مضيف بناء ARM64 متصل بالإنترنت، اجمع تبعيات أداة المضيف باستخدام صورة Ubuntu 24.04 محلية واضحة. استخدم معرف الصورة الذي تم التحقق منه على ذلك المضيف، وليس معرفًا منسوخًا من جهاز تطوير:

   ```sh
   python3 install/collect_host_packages.py \
     --base-image "$UBUNTU_ARM64_IMAGE_ID" --output /build/artifacts/host-packages
   ```

   اجمع فقط التبعيات الخاصة بـ cryptsetup وext4 وUSB/الكاميرات وأدوات صور QEMU والشبكات وأدوات النظام الصغيرة. يُحظر استخدام حزم Docker وcontainerd وNVIDIA وCUDA وkernel البديلة. لوازم التثبيت تفتقد الأدوات فقط؛ يقرأ apt مستودع الملفات المحلي الخاص بالحزمة باستخدام `--no-download --no-remove`، دون الرجوع إلى الإنترنت.

5. قم بإنشاء بيان إدخال الإصدار وتوفير ** مسارات المنتجات الصريحة ومعرفات محتوى الصورة المحلية **:

   ```sh
   python3 install/prepare-release.py --template /build/artifact-inputs.json
   python3 install/prepare-release.py --inputs /build/artifact-inputs.json \
     --output /build/prepared-release
   ```

   يتضمن القالب جميع أدوار الصور الـ 41 وفئات الأصول الخارجية الـ 12؛ يتم إنشاء أصول مصنع أخرى بواسطة الأدوات. لا يمكن للعناصر النائبة إدخال حزمة. يجب أن يتطابق `sourceCommit` مع عملية الدفع، و`agentVersion` بناء الوكيل الفعلي، و`hostPackageCollection` الخطوة 4 `collection.json`. مسارات بناء المضيف هي مدخلات المجموعة، وليست تكوين وقت تشغيل العميل. استخدم منشئ المصنع الحالي: يجب أن تتطابق مسارات واجهة المستخدم للرسم `drawing.automatic` / `drawing.fast` مع تكوين النموذج المحلي. صحة العامل أو استدعاء النموذج المباشر وحده لا يثبت جاهزية التطبيق. يرفض التغليف قوالب المصنع التي لا معنى لها والتي تفتقد هذه التعيينات.

تم الإبلاغ عن عقد دور الصورة بواسطة `python3 install/package.py --describe-contract`:

- النواة، والويب، ومحرك الفريق، والمراسلة، والبوابات، والمجدول، والصيانة، والمكونات الإضافية، وصناديق حماية الوكيل الديناميكي، وبوابات مصدر الحزمة.
- تسعة مكونات إضافية للتطبيقات وستة نماذج مكتبية عاملة وأوقات تشغيل ASR/مكبر الصوت عند الطلب.
- Android القياسي، وGoogle Android، ووقت تشغيل الكمبيوتر، وبوابات العرض/الصوت على الويب.
- استقبال الصب ومعالجة الوسائط وSFU.

يمكن لدورين مشاركة معرف محتوى صورة واحد؛ يتم تصدير أرشيفه مرة واحدة فقط. يتم التحقق من فهارس أجزاء النموذج أيضًا: لا تعفي تجزئات الملف المطابقة وجود جزء مفقود. يجب أن تكون أدوات المضيف عبارة عن ثنائيات ARM64 ELF فعلية.

## بناء الحزمة

```sh
./install/build-package.sh --release /build/prepared-release/release-input.json \
  --output /build/output
```

المخرجات هي `teamaibox-<releaseId>-linux-arm64.tar` وملفها `.sha256` والدليل المستخرج. يتم النسخ وتصدير الصور والتجزئة والأرشفة في دليل مؤقت قبل نشر المجموع الاختباري النهائي. لا تتم الكتابة فوق المخرجات الموجودة؛ يجب ألا يبدو البناء المتقطع كإصدار كامل. بالنسبة للتغييرات التي تم إجراؤها بواسطة برنامج التثبيت فقط مع عدم تغيير هويات الصور، استخدم `--image-cache <previous-extracted-package>`. يتم التحقق من الحزمة القديمة بالكامل قبل إعادة استخدام أرشيفاتها بواسطة معرف الصورة الفعلي، ويتم التحقق من الحزمة الجديدة مرة أخرى. لا يتم أخذ أي بيانات من التثبيت القديم أو الطبقة القابلة للكتابة على الحاوية. يؤدي هذا إلى تجنب تصدير مئات الجيجابايت من الصور المتطابقة مرة أخرى.

يتطلب الإصدار العادي أن تنتمي ملفات المصدر المجمعة إلى التزام Git المعلن. يقوم `--allow-working-tree` الصريح بإنشاء مرشح تطوير؛ يسجل بيانه `candidate: true` والملفات المتغيرة. لا يؤدي تمرير القبول المركّز إلى تحويل المصدر المتاح إلى إصدار منشور.

تخطيط الحزمة:

```text
teamaibox-<releaseId>-linux-arm64/
  install.sh, installer.py, offline_common.py, offline_host_packages.py
  README.zh-CN.md, release.json, checksums.sha256
  images/          # Docker archives deduplicated by content ID
  assets/          # Models, Android, computers, tools and factory configuration by role
  host-packages/   # Complete .deb dependency set
  runtime/         # Installer adapters and recovery-tool module closure
```

تحقق بشكل مستقل باستخدام `./install/build-package.sh --verify /build/output/teamaibox-<releaseId>-linux-arm64`. هذا يتحقق من النزاهة؛ لا يثبت نجاح التمهيد على الأجهزة الجديدة.

## العملاء: التثبيت والاستئناف دون اتصال بالإنترنت

اقرأ [دليل تثبيت الحزمة](PACKAGE-README.ar.md). الجذر الافتراضي هو `/srv/teamaibox/installation`. يتم إنشاء LUKS/ext4 فقط داخل `volume/data.img` الجديد، وليس على قرص النظام أو الأقراص الموجودة. يستخدم مجمع البيانات مساحة التخزين المتاحة مطروحًا منها هامش الأمان الفعلي، وليس حدًا ثابتًا يبلغ 256 جيجا بايت. النماذج وملفات الأعمال وبيانات الضيوف موجودة في المجلد المشفر؛ يقوم Docker الحالي بإدارة صور الحاوية.

يؤدي التثبيت الجديد إلى إنشاء المسؤول `admin` بكلمة المرور الأولية `admin`. يتم إنشاء المستخدمين العاديين من قبل المسؤول. قم بتغيير كلمة المرور الأولية قبل التسليم/الاستخدام. ينطبق هذا فقط على قاعدة بيانات الحسابات الفارغة: لا يؤدي الاستئناف وإعادة التشغيل وإعادة التشغيل والترقية إلى إعادة تعيين الحسابات أو كلمات المرور الموجودة. يتم إنشاء هوية الجهاز وبيانات اعتماد الخدمة والشهادات ورموز استرداد المسؤول بشكل مستقل، ولا يتم نسخها من جهاز آخر. يتم تشغيل الإعداد الأولي لذاكرة التخزين المؤقت لنواة وحدة معالجة الرسومات على الجهاز باستخدام الأدوات والنماذج المجمعة؛ يتم الاحتفاظ بذاكرة التخزين المؤقت المتوافقة. يعمل استرداد التمهيد على استعادة البيانات وخدمات الأجهزة أولاً، ثم الخدمات الأساسية والعاملين الفرديين الذين يعملون في مجال الذكاء الاصطناعي. يعمل المثبت أثناء التثبيت فقط؛ لا يضيف أي مدير التثبيت المقيم.

بعد المقاطعة، كرر الأمر الأصلي. يتم التحقق من الخطوات المكتملة. لا تخفي التعارضات عن طريق حذف البيانات أو إعادة إنشاء الحاويات. تؤدي إعادة تشغيل تثبيت الإصدار نفسه المكتمل إلى التحقق منه فقط؛ تستخدم الإصدارات المختلفة مسار الترقية الرسمي. تفاصيل الفشل موجودة في `install-state.json`, `readiness.json` وسجلات المرحلة ضمن جذر التثبيت.

## حدود التحقق

تستخدم الاختبارات الخاصة بالمثبت عناصر هيكلية صغيرة وملفات مؤقتة وقواعد بيانات معزولة غير متصلة بالإنترنت/برامج Docker. يجب ألا يصلوا إلى قواعد بيانات الأعمال أو يقومون بتحميل أقراص VM الموجودة. يتطلب التثبيت الجديد الحقيقي DGX Spark متوافقًا ومخصصًا بشكل صريح لهذا الغرض؛ لا تقم بمسح جهاز الأعمال. يغطي القبول الحد الأدنى من بدء التشغيل والاستئناف واسترداد التمهيد للتثبيت الجديد، وليس اختبارات الأعمال غير ذات الصلة. لا يؤدي إعداد إصدار المصدر في حد ذاته إلى مسح الأجهزة الموجودة أو إعادة تثبيتها أو نشرها.

على مضيف بناء، قم بتشغيل `sudo python3 install/verify_bundle_offline.py --package <extracted-package> --output <new-test-directory>` لاستيراد الحزمة الكاملة إلى برنامج Docker منفصل بذاكرة تخزين مؤقت فارغة ولا توجد شبكة عامة. ولا يقوم باستدعاء البرنامج النصي للتثبيت الجديد، أو استخدام وحدة معالجة الرسومات، أو تحميل أدلة العملاء، أو إعادة تشغيل Docker النظام. ولا يطالب تقريرها صراحة بالتثبيت الكامل للأجهزة. تظل صور الاختبار في دليل الاختبار المخصص، وتحتاج إلى مساحة قرص إضافية ولا تدخل إلى مخزن صور Docker الخاص بالنظام.
