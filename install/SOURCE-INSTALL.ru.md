# Установка из общедоступного клона

Эта точка входа подготавливает необходимые общедоступные входные данные, создает образы приложения и создает полный пакет перед его установкой. Прогресс сборки возобновляется; только окончательный результат готовности к установке указывает на установленное устройство. Успех загрузки или предполетной проверки сам по себе не имеет значения.

Храните сгенерированные модели, образы контейнеров, установочные пакеты, записи испытаний и учетные данные вне репозитория. Доступность стороннего зеркала не гарантируется; проверенные портативные кэши и автономные пакеты описаны ниже.

На свежем DGX Spark с Ubuntu 24.04, работающим Docker/Compose, NVIDIA и KVM клонируйте публичный репозиторий и запустите из его корня:

```sh
git clone https://github.com/weerocksllc/teamaibox.git
cd teamaibox
sudo bash install/from-source.sh
```

Для сети материкового Китая, где недоступны исходные конечные точки модели/изображения, используйте ту же точку входа с региональными источниками загрузки:

```sh
sudo bash install/from-source.sh --region cn
```

Это **сборка исходного кода в Интернете с последующей установкой в автономном режиме**, а не сборка исходного кода в автономном режиме. Он автоматически подготавливает недостающие инструменты сборки, загружает шесть входных данных модели, собирает и собирает Android и все образы приложений, квантует две исходные модели, собирает пакеты прошивки/хоста, создает полный автономный пакет и запускает существующий установщик. Он не заменяет Docker/NVIDIA, не перезапускает демон Docker, не очищает существующую установку и не изменяет маршрутизацию хоста, настройки DNS или VPN. Модели, состояния гостевого входа и частный маркетинговый веб-сайт не берутся из другой установки.

Рабочее пространство по умолчанию — `/var/tmp/teamaibox-source-build`; Кэши загрузок и журналы каждого этапа хранятся там, за пределами клона. По умолчанию при установке используется `/srv/teamaibox/installation`. Ожидайте больших загрузок и нескольких сотен ГБ временного использования диска. Загрузка модели и квантование графического процессора могут занять значительное время; фиксированное время завершения не обещано.

## Возобновление установки и состояние

В случае прерывания **повторно запустите ту же команду**. Сохраняйте рабочее место. Работающая сборка исключает другого писателя; завершенные файлы этапов и изображения проверяются перед повторным использованием. Неудачные попытки остаются доступными для диагностики, а следующая попытка запускает только неудачный этап. Диапазоны байтов модели и проверенные файлы сохраняются. `state.json` идентифицирует текущий этап и каталог его журналов. Официальные загрузки моделей используют ограниченный параллелизм файлов/диапазонов; региональные источники используют консервативный параллелизм, чтобы уменьшить ограничение скорости. Отчеты о ходе выполнения каждого файла в байтах передаются или повторно используются отдельно от окончательной проверки хеша издателя. Компиляция гостевых инструментов также работает в рамках системной службы без входа в систему: она создает изолированные кэши сборки вне результирующих ресурсов установки.

Для изменения исходного кода требуется новый `--work-dir`; повторно используйте кэш загрузки с помощью `--cache-dir /path/to/public-cache`. Отпечаток источника предотвращает автоматическое объединение выходных данных из разных кодов. Существующая установка не является приглашением к ее сбросу: возобновиться может только установка того же пакета в этой рабочей области; другие установки должны использовать свой процесс обновления.

Полезные режимы:

```sh
sudo bash install/from-source.sh --check
sudo bash install/from-source.sh --region cn --download-models-only
sudo bash install/from-source.sh --region cn --build-only
```

`--check` доступен только для чтения и не утверждает, что загрузка будет успешной. Только загрузка и только сборка явно не заявляют о готовности к установке.

## Региональные источники и целостность

В режиме Китая используется `https://hf-mirror.com` для передачи модели и `https://docker.m.daocloud.io` для входных данных Docker Hub, закрепленных в дайджесте. Это сторонние зеркала, а не сервисы Weerocks или издателей моделей. Коммит модели Git закреплен за профилем продукта; его проверенное дерево Git и указатели LFS определяют ожидаемые размеры файлов и хэши. Ответ API зеркала сам по себе не может установить доверие. Docker проверяет закрепленные дайджесты манифеста/слоя. Незакрепленные теги не перенаправляются автоматически (инструмент сборки Go имеет явную блокировку дайджеста). Изображения NVIDIA остаются в реестре издателя. Проверка TLS остается включенной, и токены учетной записи не отправляются на зеркала модели.

Вы можете выбрать собственное происхождение HTTPS, используя `--model-endpoint` and `--registry-mirror`. Значения конечной точки не должны включать учетные данные или параметры запроса. Оболочка Docker с заданной областью применяется только к этому процессу сборки, а не к системному демону или другим проектам. Метаданные SDK и архивы лицензий по-прежнему поступают от авторитетных издателей HTTPS; зеркало не может изобретать хеши.

Зеркала могут быть ограничены по скорости или недоступны. Загрузка моделей выполняется с ограниченным параллелизмом и с учетом времени восстановления. Ни один сценарий не может гарантировать подключение к каждому восходящему каналу в каждой сети. Если оба маршрута недоступны, подготовьте загрузки или полный пакет на доступном совместимом компьютере и скопируйте их:

- `--download-models-only --cache-dir <public-cache>` подготавливает проверенные файлы модели и возобновляемые кэши. Скопируйте этот каталог, затем передайте его с помощью `--cache-dir` в цель. Каждая повторно используемая модель проверяется на соответствие закрепленному идентификатору. Этот кэш **не** является полным пакетом автономной установки.
- `--build-only` подготавливает полный пакет для автономной установки. Скопируйте его tar и контрольную сумму, проверьте и распакуйте, затем запустите внутри него `sudo ./install.sh`. Это надежный маршрут с отключенным хостом; для этого не требуется VPN на цели или доступ к программному обеспечению.

Никогда не копируйте действующий каталог данных Docker, гостевые диски, профили браузера, базы данных учетных записей, учетные данные или частные кеши вместо общедоступных входных данных. Не отключайте контрольные суммы и не принимайте страницу входа/вызова в качестве файла модели.

## Лицензирование и первое использование

Перед сборкой ознакомьтесь с `THIRD_PARTY_NOTICES.md`, условиями Android SDK и лицензиями на отдельные модели. Загрузка сторонних компонентов не превращает их в ресурсы MIT и не предоставляет права сертификации/распространения Google. ISO-носители Windows/Linux по-прежнему предоставляются пользователем. Заводской логин остается `admin/admin`; замените его, прежде чем подвергать прибор воздействию. Существующий установщик генерирует независимые учетные данные службы и сообщает о фактической готовности.

После завершения откройте `https://<BOX_LAN_IP>/` в той же локальной сети; замените текущий адрес физической сети Spark, а не мост Docker или адрес VPN. `state.json` исходной рабочей области записывает ход сборки. Установленный `/srv/teamaibox/installation/readiness.json` записывает проверки установки. Ни успешная компиляция, ни проверка работоспособности контейнера прослушивания не заменяют видимую сквозную работу приложения.

Среда выполнения кастинга должна содержать приемник UxPlay, частные исполняемые файлы D-Bus и обнаружения Avahi, а также медиа-плагины. Окончательная сборка общедоступного образа проверяет эти исполняемые файлы; одной клиентской библиотеки недостаточно. При новой установке прокси-сервер и шлюз рабочего стола регистрируются с другими зависимыми от сетевого пространства имен API, поэтому сгруппированные обновления API могут сохранить путь подключения к рабочему столу. Не воссоздавайте только подмножество этой группы во время обслуживания.
