# 공개 클론에서 설치

이 진입점은 필요한 공개 입력을 준비하고, 애플리케이션 이미지를 빌드하고, 설치하기 전에 완전한 패키지를 생성합니다. 빌드 진행이 재개 가능합니다. 최종 설치 준비 결과만 설치된 기기를 나타냅니다. 다운로드나 프리플라이트 성공만으로는 성공할 수 없습니다.

생성된 모델, 컨테이너 이미지, 설치 패키지, 테스트 기록 및 자격 증명을 리포지토리 외부에 보관하세요. 타사 미러 가용성은 보장되지 않습니다. 검증된 휴대용 캐시 및 오프라인 패키지는 아래에 설명되어 있습니다.

Ubuntu 24.04가 설치된 새로운 DGX Spark에서 Docker/Compose, NVIDIA 및 KVM을 작동하면서 공개 저장소를 복제하고 해당 루트에서 실행합니다.

```sh
git clone https://github.com/weerocksllc/teamaibox.git
cd teamaibox
sudo bash install/from-source.sh
```

업스트림 모델/이미지 엔드포인트에 연결할 수 없는 중국 본토 네트워크의 경우 지역 다운로드 소스와 동일한 진입점을 사용합니다.

```sh
sudo bash install/from-source.sh --region cn
```

이는 오프라인 소스 빌드가 아닌 **온라인 소스 빌드 후 오프라인 설치**입니다. 누락된 빌드 도구를 자동으로 준비하고, 6개 모델 입력을 다운로드하고, Android 및 모든 애플리케이션 이미지를 빌드 및 어셈블하고, 두 소스 모델을 양자화하고, 펌웨어/호스트 패키지를 수집하고, 완전한 오프라인 패키지를 생성하고, 기존 설치 프로그램을 실행합니다. Docker/NVIDIA를 대체하거나, Docker 데몬을 다시 시작하거나, 기존 설치를 지우거나, 호스트 라우팅, DNS 또는 VPN 설정을 변경하지는 않습니다. 모델, 게스트 로그인 상태 및 개인 마케팅 웹사이트는 다른 설치에서 가져오지 않습니다.

기본 작업공간은 `/var/tmp/teamaibox-source-build`입니다. 다운로드 캐시와 단계별 로그는 복제본 외부에 있습니다. 설치 기본값은 `/srv/teamaibox/installation`입니다. 대규모 다운로드와 수백 GB의 임시 디스크 사용량이 예상됩니다. 모델 로딩 및 GPU 양자화에는 상당한 시간이 걸릴 수 있습니다. 고정된 완료 시간은 약속되지 않습니다.

## 중단 후 재개 및 진행 상태

중단되면 **정확히 동일한 명령을 다시 실행**하세요. 작업 공간을 유지하세요. 실행 중인 빌드는 다른 작성자를 제외합니다. 완성된 스테이지 파일과 이미지는 재사용 전에 검증됩니다. 실패한 시도는 진단에 계속 사용할 수 있지만 다음 시도에서는 실패한 단계만 실행됩니다. 모델 바이트 범위와 확인된 파일이 유지됩니다. `state.json`는 현재 단계와 해당 로그 디렉터리를 식별합니다. 공식 모델 다운로드는 제한된 파일/범위 동시성을 사용합니다. 지역 소스는 보수적인 동시성을 사용하여 속도 제한을 줄입니다. 파일별 바이트 진행률은 최종 게시자 해시 확인과 별도로 전송되거나 재사용된 범위를 보고합니다. 게스트 도구 컴파일은 로그인 홈이 없는 시스템 서비스에서도 작동합니다. 결과 설치 자산 외부에 격리된 빌드 캐시를 생성합니다.

소스 변경에는 새로운 `--work-dir`가 필요합니다. `--cache-dir /path/to/public-cache`로 다운로드 캐시를 재사용합니다. 소스 지문은 다른 코드의 출력을 자동으로 결합하는 것을 방지합니다. 기존 설치는 재설정하라는 초대가 아닙니다. 이 작업 영역의 동일한 패키지 설치만 재개될 수 있습니다. 다른 설치에서는 업그레이드 프로세스를 사용해야 합니다.

유용한 모드:

```sh
sudo bash install/from-source.sh --check
sudo bash install/from-source.sh --region cn --download-models-only
sudo bash install/from-source.sh --region cn --build-only
```

`--check`는 읽기 전용이며 다운로드가 성공할 것이라고 주장하지 않습니다. 다운로드 전용 및 빌드 전용은 설치된 준비 상태를 명시적으로 주장하지 않습니다.

## 지역 소스 및 무결성

중국 모드는 모델 전송에 `https://hf-mirror.com`를 사용하고 다이제스트 고정 Docker Hub 입력에 `https://docker.m.daocloud.io`를 사용합니다. 이는 Weerocks나 모델 출판사가 운영하는 서비스가 아닌 제3자 미러입니다. 모델 Git 커밋은 제품 프로필에 의해 고정됩니다. 검증된 Git 트리와 LFS 포인터는 예상되는 파일 크기와 해시를 설정합니다. 미러의 API 응답만으로는 신뢰를 구축할 수 없습니다. Docker는 고정된 매니페스트/레이어 다이제스트를 확인합니다. 고정 해제된 태그는 자동으로 리디렉션되지 않습니다(Go 빌드 도구에는 명시적인 다이제스트 잠금이 있음). NVIDIA 이미지는 게시자의 레지스트리에 남아 있습니다. TLS 확인은 활성화된 상태로 유지되며 계정 토큰은 모델 미러로 전송되지 않습니다.

`--model-endpoint` and `--registry-mirror`를 사용하여 자체 HTTPS 원본을 선택할 수 있습니다. 엔드포인트 값에는 자격 증명이나 쿼리 매개변수가 포함되어서는 안 됩니다. 범위가 지정된 Docker 래퍼는 이 빌드 프로세스에만 적용되며 시스템 데몬이나 다른 프로젝트에는 적용되지 않습니다. SDK 메타데이터 및 라이선스 아카이브는 여전히 신뢰할 수 있는 HTTPS 게시자로부터 제공됩니다. 미러는 해시를 생성할 수 없습니다.

미러는 속도가 제한되거나 사용 불가능할 수 있습니다. 모델 다운로드는 제한된 동시성과 존중된 휴지 시간으로 실행됩니다. 어떤 스크립트도 모든 네트워크의 모든 업스트림에 대한 연결을 보장할 수 없습니다. 두 경로를 모두 사용할 수 없는 경우 액세스 가능한 호환 시스템에서 다운로드 또는 전체 패키지를 준비하고 복사하세요.

- `--download-models-only --cache-dir <public-cache>`는 검증된 모델 파일과 재개 가능한 캐시를 준비합니다. 해당 디렉터리를 복사한 다음 대상에 `--cache-dir`와 함께 전달합니다. 재사용된 모든 모델은 고정된 ID와 비교하여 확인됩니다. 이 캐시는 전체 오프라인 설치 패키지가 **아닙니다**.
- `--build-only`는 오프라인 설치를 위해 전체 패키지를 준비합니다. tar와 체크섬을 복사하고 확인하고 압축을 푼 다음 그 안에서 `sudo ./install.sh`를 실행하세요. 이는 신뢰할 수 있는 연결이 끊긴 호스트 경로입니다. 대상에 VPN이 필요하지 않으며 개발 상자에 액세스할 필요도 없습니다.

공개 입력 대신 라이브 Docker 데이터 디렉터리, 게스트 디스크, 브라우저 프로필, 계정 데이터베이스, 자격 증명 또는 개인 캐시를 복사하지 마세요. 체크섬을 비활성화하거나 로그인/챌린지 페이지를 모델 파일로 수락하지 마십시오.

## 라이선스 및 최초 사용

빌드하기 전에 Android SDK 약관 및 개별 모델 라이선스인 `THIRD_PARTY_NOTICES.md`를 검토하세요. 타사 구성요소를 다운로드해도 해당 구성요소가 MIT 자산으로 전환되거나 Google 인증/재배포 권한이 부여되지 않습니다. Windows/Linux ISO 미디어는 여전히 사용자가 제공합니다. 공장 로그인은 `admin/admin`로 유지됩니다. 제품을 노출하기 전에 교체하십시오. 기존 설치 프로그램은 독립적인 서비스 자격 증명을 생성하고 실제 준비 상태를 보고합니다.

완료 후 동일한 LAN에서 `https://<BOX_LAN_IP>/`를 엽니다. Docker 브리지나 VPN 주소가 아닌 Spark의 현재 물리적 네트워크 주소를 대체하세요. 소스 작업공간의 `state.json`는 빌드 진행 상황을 기록합니다. 설치된 `/srv/teamaibox/installation/readiness.json`는 설치 확인을 기록합니다. 성공적인 컴파일이나 수신 컨테이너 상태 확인은 애플리케이션의 가시적인 엔드투엔드 작업을 대체하지 않습니다.

캐스팅 런타임에는 UxPlay 수신기, 개인 D-Bus 및 Avahi 검색 실행 파일과 해당 미디어 플러그인이 포함되어야 합니다. 최종 공개 이미지 빌드에서는 이러한 실행 파일을 확인합니다. 클라이언트 라이브러리만으로는 부족합니다. 새로 설치하면 데스크톱 프록시와 게이트웨이가 다른 API 네트워크 네임스페이스 종속 항목에 등록되므로 그룹화된 API 업그레이드에서 데스크톱 연결 경로를 유지할 수 있습니다. 유지 관리 중에는 해당 그룹의 하위 집합만 다시 생성하지 마세요.
