# среда выполнения виртуального компьютера ARM

`Public.Dockerfile` создает ту же возможность физического присутствия (PPI) ARM TPM, которая требуется для исходной среды выполнения `windows-arm64-ppi`. Он собирает QEMU 11.1.1 из официального выпуска после сверки его отдельной подписи с прикрепленным отпечатком менеджера релизов. Debian предоставляет библиотеки и инструменты контейнеров, а не исполняемый файл QEMU, используемый для запуска гостевых систем.

Не заменяйте этот исполняемый файл более старым дистрибутивным пакетом QEMU. Профили Windows включают `tpm-tis-device,...,ppi=on`; сборка без этого свойства ARM завершается до начала прошивки. Удаление `ppi=on`, отключение TPM или сброс гостевого TPM не являются совместимым ремонтом.

Окончательная сборка образа проверяет поддержку ARM TIS PPI и PulseAudio и включает соответствующее ПЗУ кадрового буфера RAM. На хосте ARM KVM встроенный `python3 /usr/local/bin/probe-ppi` выполняет бездисковую приостановленную проверку QEMU/TPM. Он не монтирует существующие гостевые диски и не подтверждает завершение установки Windows. Загрузку Windows необходимо проверять отдельно на явно назначенном тестовом госте.

Для существующей установки используйте политику обновления во время выполнения платформы и соответствующий дайджест образа профиля агента узла. Сохраните диск, прошивку, идентификатор и состояние TPM. Не пересоздавайте гостевые системы и не изменяйте работающие гостевые образы Linux только для восстановления среды выполнения Windows. Записывайте локально созданные образы как неопубликованные до тех пор, пока их исходные изменения не будут зафиксированы и выпущены.

Сохраните право собственности на установленную конфигурацию и права на чтение при ее обновлении. Если API платформы воссоздается для загрузки политики обновления во время выполнения, также воссоздайте его зависимости от сетевого пространства имен (`node-agent`, `appliance-gateway`, `desktop-proxy`, `desktop-gateway` и `maintenance-controller`) из их неизмененных образов. Они должны присоединиться к сетевому пространству имен нового контейнера API. Это не гость, демон Docker или перезагрузка AI-работника. Подождите, пока нормальный аутентифицированный контрольный сигнал узла восстановит готовность, прежде чем отправлять операцию запуска Windows.
