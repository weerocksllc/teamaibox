# وقت تشغيل الكمبيوتر الافتراضي ARM

يبني `Public.Dockerfile` نفس إمكانية التواجد الفعلي (PPI) لـ ARM TPM التي يتطلبها وقت التشغيل الأصلي `windows-arm64-ppi`. يقوم ببناء QEMU 11.1.1 من الإصدار الرسمي بعد التحقق من توقيعه المنفصل مقابل بصمة مدير الإصدار المثبتة. يوفر دبيان مكتبات وأدوات الحاويات، وليس الملف القابل للتنفيذ QEMU المستخدم لتشغيل الضيوف.

لا تستبدل هذا الملف القابل للتنفيذ بحزمة QEMU للتوزيع الأقدم. تعمل ملفات تعريف Windows على تمكين `tpm-tis-device,...,ppi=on`؛ يتم إنهاء البناء الذي لا يحتوي على خاصية ARM قبل بدء تشغيل البرنامج الثابت. إن إزالة `ppi=on` أو تعطيل TPM أو إعادة تعيين TPM الخاص بالضيف ليس إصلاحًا متوافقًا.

يتحقق إنشاء الصورة النهائية من دعم ARM TIS PPI وPulseAudio ويتضمن ذاكرة الوصول العشوائي (RAM) المتوافقة مع ذاكرة الوصول العشوائي (RAM). على مضيف ARM KVM، يقوم `python3 /usr/local/bin/probe-ppi` بإجراء فحص QEMU/TPM بدون أقراص ومتوقف مؤقتًا. ولا يقوم بتحميل أقراص الضيف الموجودة أو يثبت اكتمال تثبيت Windows. يجب فحص تمهيد Windows بشكل منفصل على ضيف اختبار معين بشكل صريح.

بالنسبة للتثبيت الحالي، استخدم سياسة تحديث وقت التشغيل للنظام الأساسي وملخص صورة ملف تعريف Node Agent المطابقة. الحفاظ على القرص والبرامج الثابتة وهوية TPM وحالته. لا تقم بإعادة إنشاء الضيوف أو تغيير صور ضيوف Linux قيد التشغيل فقط لإصلاح وقت تشغيل Windows. قم بتسجيل الصور التي تم إنشاؤها محليًا على أنها غير منشورة حتى يتم الالتزام بالتغييرات في مصدرها وإصدارها.

احتفظ بملكية التكوين المثبت وأذونات القراءة عند تحديثه. إذا تمت إعادة إنشاء Platform API لتحميل سياسة تحديث وقت التشغيل، فأعد أيضًا إنشاء العناصر التابعة لمساحة اسم الشبكة (`node-agent`, `appliance-gateway`, `desktop-proxy`, `desktop-gateway` و`maintenance-controller`) من صورهم التي لم تتغير. ويجب عليهم الانضمام إلى مساحة اسم الشبكة الخاصة بحاوية API الجديدة. هذه ليست عملية إعادة تشغيل ضيف أو برنامج Docker الخفي أو إعادة تشغيل عامل الذكاء الاصطناعي. انتظر حتى يتم مصادقة نبضات العقدة الطبيعية لاستعادة الاستعداد قبل إرسال عملية بدء تشغيل Windows.
