# รันไทม์คอมพิวเตอร์เสมือน ARM

`Public.Dockerfile` สร้างความสามารถการแสดงตนทางกายภาพ (PPI) ของ ARM TPM แบบเดียวกับที่จำเป็นสำหรับรันไทม์ `windows-arm64-ppi` ดั้งเดิม สร้าง QEMU 11.1.1 จากรุ่นอย่างเป็นทางการหลังจากตรวจสอบลายเซ็นที่แยกออกมากับลายนิ้วมือผู้จัดการรุ่นที่ปักหมุดไว้ Debian จัดเตรียมไลบรารีคอนเทนเนอร์และเครื่องมือ ไม่ใช่ไฟล์ปฏิบัติการ QEMU ที่ใช้ในการรันเกสต์

อย่าแทนที่ไฟล์ปฏิบัติการนี้ด้วยแพ็คเกจ QEMU การแจกจ่ายรุ่นเก่า โปรไฟล์ Windows เปิดใช้งาน `tpm-tis-device,...,ppi=on`; บิลด์ที่ไม่มีคุณสมบัติ ARM นั้นออกก่อนที่เฟิร์มแวร์จะเริ่มทำงาน การลบ `ppi=on` การปิดใช้งาน TPM หรือการรีเซ็ต TPM ของแขกไม่ใช่การซ่อมแซมที่เข้ากันได้

การสร้างอิมเมจขั้นสุดท้ายจะตรวจสอบการรองรับ ARM TIS PPI และ PulseAudio และรวม RAM framebuffer ROM ที่ตรงกัน บนโฮสต์ ARM KVM ชุด `python3 /usr/local/bin/probe-ppi` จะทำการตรวจสอบ QEMU/TPM ที่หยุดชั่วคราวโดยไม่ใช้ดิสก์ ไม่ได้ติดตั้งดิสก์แขกที่มีอยู่หรือพิสูจน์ว่าการติดตั้ง Windows เสร็จสมบูรณ์ จะต้องตรวจสอบการบูต Windows แยกต่างหากจากผู้ทดสอบที่ได้รับมอบหมายอย่างชัดเจน

สำหรับการติดตั้งที่มีอยู่ ให้ใช้นโยบายการอัพเดตรันไทม์ของแพลตฟอร์มและการสรุปอิมเมจโปรไฟล์ Node Agent ที่ตรงกัน เก็บรักษาดิสก์ เฟิร์มแวร์ ข้อมูลระบุตัวตนและสถานะ TPM อย่าสร้างเกสต์ขึ้นใหม่หรือเปลี่ยนแปลงการรันอิมเมจเกสต์ของ Linux เพียงเพื่อซ่อมแซมรันไทม์ของ Windows บันทึกรูปภาพที่สร้างขึ้นในเครื่องว่ายังไม่ได้เผยแพร่จนกว่าการเปลี่ยนแปลงแหล่งที่มาจะได้รับการยืนยันและเผยแพร่

รักษาความเป็นเจ้าของการกำหนดค่าที่ติดตั้งไว้และสิทธิ์ในการอ่านเมื่อทำการอัพเดต หากมีการสร้างแพลตฟอร์ม API ขึ้นใหม่เพื่อโหลดนโยบายการอัปเดตรันไทม์ ให้สร้างเนมสเปซเครือข่ายขึ้นใหม่ (`node-agent`, `appliance-gateway`, `desktop-proxy`, `desktop-gateway` และ `maintenance-controller`) จากอิมเมจที่ไม่เปลี่ยนแปลง พวกเขาจะต้องเข้าร่วมเนมสเปซเครือข่ายของคอนเทนเนอร์ API ใหม่ นี่ไม่ใช่แขก, Docker daemon หรือการรีสตาร์ทผู้ปฏิบัติงาน AI รอให้ฮาร์ตบีตที่ผ่านการรับรองความถูกต้องตามปกติของโหนดเพื่อคืนความพร้อมก่อนส่งการดำเนินการเริ่มต้น Windows
